\index{tensor!shape}

\begin{outcomes}
\outcome{1--8}{read a shape as a tuple of axis lengths, and say what a given
  number taken out of one is counting}
\outcome{9--15}{write an operation on arrays in index notation, and say from
  the indices alone which axes survive it}
\outcome{16--22}{read an \code{einsum} string as the sum it denotes, and write
  one for an operation given in words}
\outcome{23--30}{apply the broadcasting rule exactly, and recognise the shapes
  that pair up in a way nobody asked for}
\outcome{31--37}{say which of reshape, transpose and permute moves data, and
  which order splits a batch into heads correctly}
\end{outcomes}

\begin{quiz}
\item An array has shape $(\val{p07.emb.b}, \val{p07.emb.s}, \val{p07.emb.d})$.
  How many numbers is that, and how many axes? \teachesat{7--8}
  \answerto{$\val{p07.emb.total}$ numbers across $\val{p07.emb.rank}$ axes. The
  count is the product of the lengths; the number of axes is how many lengths
  there are, and the two answer different questions.}
\item In $\sum_k A_{ik} B_{kj}$, which letters end up on the result?
  \teachesat{9--10}
  \answerto{$i$ and $j$. An index that appears twice is summed over and
  disappears; an index that appears once survives. That one line is the whole
  of index notation.}
\item What does the \code{einsum} string \code{'ij->ji'} do? \teachesat{17--18}
  \answerto{It transposes. Both indices survive and neither is summed; only
  the order they are written in has changed.}
\item Two shapes, $(n)$ and $(n, 1)$. What shape comes out of subtracting one
  from the other? \teachesat{25--26}
  \answerto{$(n, n)$. Lining the shapes up from the right pairs the $n$ with
  the $1$, which stretches, and the leading $n$ has nothing to pair with, so it
  is kept. Every pair is formed and nothing complains.}
\item Which of reshape, transpose and permute moves numbers in memory?
  \teachesat{31--32}
  \answerto{None of them, in the usual case. Each hands back the same run of
  numbers with a different rule for reading it. What moves data is asking for
  the result contiguous afterwards.}
\item An array of shape $(b, s, h \times d)$ has to become $(b, h, s, d)$.
  Is one reshape enough? \teachesat{33--34}
  \answerto{No. The reshape has to split the last axis, which gives
  $(b, s, h, d)$, and the two middle axes then have to be swapped. Reshaping
  straight to $(b, h, s, d)$ is legal, silent and a different array.}
\end{quiz}

\section{An array is a shape and a rule for reading it}
\label{sec:P07-shape}
\index{tensor!shape}

\begin{fr}
Program~\ref{prog:P06} left one thing unfinished on purpose.

It showed that a batch of $k$ inputs through a layer $W$ is a matrix of $k$
columns, one input each, and then noted that real frameworks do not do that:
they put the batch along the \emph{first} axis and compute $XW\T$ with $X$ of
shape $k \times n$.

Two conventions, and only one of them can be the layer. Which is it?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{Both.}
$XW\T$ is the transpose of $WX$, and a transpose is not a different
computation. The two conventions describe one map and disagree only about
which way up to write it down.

That is worth having as the program's first frame, because it is the last time
a question about arrays will be answerable with a matrix identity.
Program~\ref{prog:P06} had two indices and every question it asked fitted
inside them. An attention tensor has four.
\end{fr}

\begin{fr}
So the first job is a definition that survives four.

An array's \emph{shape} is a tuple of lengths. A shape of $(2, 3)$ is two rows
of three, and $(\val{p07.emb.b}, \val{p07.emb.s}, \val{p07.emb.d})$ is a batch
of sentences of vectors. An \emph{axis} is a position in that tuple.

\textbf{An axis is a position in the index tuple, not a direction in space.}
Everything else in this program is that sentence applied.
\end{fr}

\begin{fr}
Which is where a word does three jobs, and they are not compatible.

An array of shape $(\val{p07.emb.b}, \val{p07.emb.s}, \val{p07.emb.d})$ is a
batch of $\val{p07.emb.b}$ sentences, each of $\val{p07.emb.s}$ tokens, each
carrying one embedding.

Concretely: the first axis runs over the sentences in the batch, the second
over the token positions within a sentence, and the third over the numbers that
make up one token's embedding. Three axes, and three quite different things
being counted along them.

The embeddings are vectors. Program~\ref{prog:P04} would ask what the dimension
of the space they live in is. Say what it is.
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{$\val{p07.emb.d}$.}
The vectors have $\val{p07.emb.d}$ components each, so they live in a space of
$\val{p07.emb.d}$ dimensions, and Program~\ref{prog:P04}'s whole apparatus
applies to them.

\begin{trapbox}
\textbf{Calling this a three-dimensional array and then reasoning about three
dimensions is the mistake, and the word is doing the damage.}

Three things in that sentence are called a dimension, and the answer to
\enquote{what is the dimension} is different for each:

\begin{itemize}
\item the \textbf{number of axes} is $\val{p07.emb.rank}$;
\item the \textbf{length of an axis} is $\val{p07.emb.b}$,
  $\val{p07.emb.s}$ or $\val{p07.emb.d}$, depending which;
\item the \textbf{dimension of the space} a stored vector lives in is
  $\val{p07.emb.d}$, and it is a fact about one axis rather than about the
  array.
\end{itemize}

A picture makes it worse, because a picture of three axes is a picture of
three directions, and it is not that.
\end{trapbox}
\end{fr}

\begin{fr}
\begin{note}
And the number of axes is called the array's \emph{rank}, which collides with
the other thing called rank two programs from here.

Program~\ref{prog:P08} uses the word for the number of independent directions
a matrix maps onto, which is a statement about what the matrix \emph{does}. The
rank of an array is a statement about how deep the indexing goes and nothing
else. A rank-$\val{p07.emb.rank}$ array of that shape says nothing about either
one, and neither reading implies the other.

The two are far enough apart to forget and close enough to collide. This book
writes \emph{number of axes} wherever there is any doubt.
\end{note}
\end{fr}

\begin{fr}
Underneath the shape there is one flat run of numbers, and this matters more
than it sounds.

The array of shape $(\val{p07.emb.b}, \val{p07.emb.s}, \val{p07.emb.d})$ holds
how many numbers?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{$\val{p07.emb.total}$.}
The product of the lengths, which is the counting rule Program~\ref{prog:F10}
gave you.

They sit in memory in one line, and the shape is a rule for turning an index
tuple into a position in that line. For a shape $(n_0, n_1, n_2)$ the entry at
$(i, j, k)$ is at

\[ i \, n_1 n_2 + j \, n_2 + k \]

so the last index moves one step at a time and the first moves in strides of
$n_1 n_2$.

\textbf{An array is a buffer, a shape and that rule.} Section 5 is a question
about which of three operations changes which of the three, and it cannot even
be asked without this frame.
\end{fr}

\mermaidfig{p07-axes-not-directions}{What an axis is, and which of three things
called a dimension is which.}{axes are not directions}

\section{Index notation says what a picture cannot}
\label{sec:P07-indices}
\index{tensor!index notation}

\begin{fr}
Program~\ref{prog:P06} derived the matrix product as a composition. Written in
indices it is

\[ C_{ij} = \sum_k A_{ik} B_{kj} \]

which is the same statement and a different act: the composition says
\emph{why}, and this says \emph{which}.

Look at the letters rather than the sum. $i$ and $j$ appear once each on the
right; $k$ appears twice. What does the difference do?
\dotline
\nextframe
\end{fr}

\begin{fr}
\begin{ansblock}
An index that appears twice is summed over and vanishes; an index that appears
once survives onto the result.
\end{ansblock}

That is the whole rule, and it is worth stating flatly because everything left
in this program is it applied to more letters.

The sigma is then almost decoration: once you know $k$ appears twice you know
it is summed, and once you know $i$ and $j$ appear once you know the answer is
indexed by $i$ and $j$. \textbf{The shape of the result is readable off the
letters without doing any arithmetic at all.}
\end{fr}

\begin{fr}
So read one back, and this one is not the product.

\[ D_{ij} = \sum_k A_{ik} B_{jk} \]

$B$'s two indices have swapped places. What is $D$?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{$AB\T$.}
$B_{jk}$ is the entry in row $j$ and column $k$, so summing over the second
index of both is pairing row $i$ of $A$ with row $j$ of $B$ \dash{} which is
$A$ times $B$ transposed.

Which closes the loop this program opened with: $XW\T$ is a framework's layer,
and in indices it is $\sum_k X_{ik} W_{jk}$. \textbf{The transpose never had to
happen.} It is a description of which index meets which, and no array needs
turning round to satisfy it.
\end{fr}

\begin{fr}
Now four letters, on the object the program exists for.

\[ S_{bhqk} = \sum_d Q_{bhqd} K_{bhkd} \]

Ignore what it is called. Apply the rule: say which indices survive onto $S$
and which are summed away.
\dotline
\nextframe
\end{fr}

\begin{fr}
\begin{ansblock}
$b$, $h$, $q$ and $k$ survive; only $d$ is summed.
\end{ansblock}

$d$ is the only letter appearing twice \emph{and} absent from the left, so it
is the only contraction. The result has four axes, and its shape is the four
lengths of $b$, $h$, $q$ and $k$ in whatever order they were written.

\textbf{You have just read a batched multi-head attention score off the letters
without being told what any of them means.} That is the argument for the
notation in one frame: a picture of this object does not exist, and the
sentence describing it fits on one line.
\end{fr}

\begin{fr}
One refinement, because $b$ and $h$ also appear twice and are not summed.

The rule as stated is too crude. What actually decides is the left-hand side:
an index absent from the left is summed, and an index present on the left
survives however often it appears on the right. $b$ and $h$ appear on the left,
so they are \emph{batch} indices \dash{} the same computation done once for
each of them.

Delete $b$ from the left and the sum runs over it too, giving an array of three
axes rather than four and adding together things that belong to different
examples. Nothing warns. Section 3 is where that becomes something you can
type.
\end{fr}

\section{An \texorpdfstring{\code{einsum}}{einsum} string is that sentence with the sigma left out}
\label{sec:P07-einsum}
\index{tensor!einsum@\texttt{einsum}}

\begin{fr}
Here is the whole of it.

\begin{center}
\code{'ik,kj->ij'}
\end{center}

The comma separates the operands, the arrow introduces the result, and each
group of letters is one array's indices in order. Compare it with
$\sum_k A_{ik} B_{kj}$ and there is nothing in one that is not in the other.

\textbf{Everything left of the arrow that is not right of it is summed.} That
is the refinement from the last frame, written as syntax rather than as a
convention \dash{} which is why the arrow is there at all.
\end{fr}

\begin{fr}
So read three cold. Say what each one does, given two-dimensional arrays where
two are needed.

\begin{center}
\code{'ij->ji'} \qquad \code{'ii->'} \qquad \code{'ij,j->i'}
\end{center}
\dotline
\nextframe
\end{fr}

\begin{fr}
\begin{ansblock}
A transpose; the trace; a matrix times a vector.
\end{ansblock}

The first keeps both indices and reorders them. The second has $i$ twice and
nothing after the arrow, so it sums over $i$ with both operands' indices tied
together \dash{} the diagonal, added up. The third pairs the second index of a
matrix with the only index of a vector and keeps the first.

\textbf{None of the three needed a name to be read.} You applied one rule three
times, and the third is Program~\ref{prog:P06}'s \enquote{a vector is a matrix
with one column} arriving without the column.
\end{fr}

\begin{fr}
Now the other direction, which is the one worth being able to do.

You have $Q$ and $K$, both of shape (batch, head, position, feature), and you
want, for every batch and every head, the dot product of each query position
with each key position. Write the string.
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{\code{'bhqd,bhkd->bhqk'}}
Query positions are $q$, key positions are $k$, the feature axis $d$ is the one
being summed because a dot product sums over features, and $b$ and $h$ appear
on both sides because the whole thing is done once per batch element and once
per head.

That is the frame 12 sum, typed. \textbf{It is not a new idea, a library trick
or a performance feature} \dash{} it is a sigma with the sigma left out, and
anyone who can read the sum can read the string.
\end{fr}

\begin{fr}
Which leaves the one people get wrong, and it is worth walking into.

Consider \code{'bij,bjk->bik'}. Three letters appear twice: $b$, $j$ and one
more. Which of them are summed?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{Only $j$.}
$b$ appears twice on the left \emph{and} on the right, so it is a batch index:
the same matrix product done once per batch element. $i$ and $k$ appear once
each. So this is a batch of matrix products, which is what the notation is used
for more often than anything else.

\begin{trapbox}
\textbf{\enquote{Repeated means summed} is the rule people carry away, and it
is the rule for the \emph{sum}, not for the string.}

It comes from a real convention \dash{} in the traditional summation
convention there is no arrow, so repeated does mean summed and there is nothing
else it could mean. The arrow is exactly what makes a repeated index
optional, and dropping a letter from the right-hand side is how you ask for a
sum.

The cost of getting it backwards is not an error. \code{'bij,bjk->ik'} runs,
returns an array of the right shape for a single example, and has added
together results belonging to different members of the batch. The loss goes
down. The model does not learn.
\end{trapbox}
\end{fr}

\section{Broadcasting is a rule, not a courtesy}
\label{sec:P07-broadcast}
\index{tensor!broadcasting}

\begin{fr}
Adding a $(3)$ vector to a $(3, 3)$ matrix is not defined by anything you have
met, and every array library does it anyway. The thing it does is called
\emph{broadcasting} and it has an exact rule.

\begin{center}
Line the two shapes up \textbf{from the right}. Pad the shorter with $1$s in
front. A pair of axes agrees when the lengths are equal, or when one of them is
exactly $1$; if any pair does neither, the operation is refused.
\end{center}

Three sentences, and they decide every shape question in this section. Read
them again rather than paraphrasing them \dash{} the paraphrase people carry
away is \enquote{it does the sensible thing}, and it does not.
\end{fr}

\mermaidfig{p07-broadcast-alignment}{How two shapes are lined up, and what
counts as agreement.}{broadcasting alignment}

\begin{fr}
So the $(3)$ against the $(3, 3)$: padded to $(1, 3)$, the pairs are $1$ with
$3$, which stretches, and $3$ with $3$, which matches. The vector is added
along each row.

Suppose you wanted it added down each column instead. The same three numbers,
the same matrix, and no arithmetic changes. What has to?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{The shape you give the vector: $(3, 1)$.}
The pairs become $3$ with $3$ and $1$ with $3$, so the stretching happens the
other way round.

Both are legal, both run, and only one of them is what you meant. Nothing in
the arithmetic can tell you which. \textbf{The shape is the whole of the
instruction, and $(3)$ and $(3, 1)$ are different instructions.}

Which sets up the one that costs money, and it is worth answering before
reading on.

You have predictions in an array of shape $(n)$ and targets in an array of
shape $(n, 1)$ \dash{} a perfectly ordinary thing to happen, because one came
out of a model and the other out of a column of a table. You subtract one from
the other.

Apply the rule. What shape comes out?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{$(n, n)$.}
Padded to $(1, n)$, the pairs are $1$ against $n$ and $n$ against $1$. Both
stretch. So instead of $n$ differences you have $n^{2}$ of them \dash{} every
prediction against every target.

Then you square and take the mean, and the mean of $n^{2}$ numbers is a number,
so the loss is a number, so the training loop is perfectly happy.

\textbf{There is no error, no warning and no shape to inspect.} The next two
frames are about how wrong the number is, and the answer is not
\enquote{a bit}.
\end{fr}

\begin{fr}
It can be worked out exactly rather than measured, which is unusual for a bug.

Writing $p$ for the predictions and $t$ for the targets, the mean over all
pairs expands into three terms, and what comes out is

\[ \frac{1}{n^{2}}\sum_{i,j} (p_i - t_j)^{2}
   \;=\; \frac{1}{n}\sum_{i} (p_i - t_i)^{2} \;+\; 2\operatorname{Cov}(p, t). \]

The reported loss is the true loss plus twice the covariance of the predictions
with the targets.

Now the question the identity is for. Suppose the model becomes perfect, so
every prediction equals its target. What does the reported loss do?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{It stops at $2\operatorname{Var}(t)$.}
At a perfect fit the true loss is zero and the covariance is the variance of
the targets, so the reported number is $2\operatorname{Var}(t)$ and it cannot
go below it however good the model gets.

\transcript{p07-broadcast}

Three predictions equal to their three targets: the true loss is $0$ and the
reported one is $\val{p07.demo.floor}$, which is twice the variance of
$1, 2, 3$.

\textbf{What an engineer sees is a loss that falls, flattens at a number nobody
can account for, and stays there.} That is read as a model that has stopped
learning, and it is a missing argument on one line.
\end{fr}

\begin{fr}
Measured on $\val{p07.mse.n}$ examples at two noise levels, and the direction
is the part worth keeping.

\begin{center}
\begin{tabular}{lrr}
\toprule
 & true loss & reported \\
\midrule
a poor fit & $\val{p07.mse.true.hi}$ & $\val{p07.mse.bcast.hi}$ \\
a good fit & $\val{p07.mse.true.lo}$ & $\val{p07.mse.bcast.lo}$ \\
\bottomrule
\end{tabular}
\end{center}

At the poor fit the reported loss is $\val{p07.mse.ratio.hi}$ times the true
one. At the good fit it is $\val{p07.mse.ratio.lo}$ times.

\textbf{The better the model gets, the more the reported number lies}, because
the excess is twice a covariance and a covariance is exactly what training
increases. A bug that is mild while you are debugging and severe once things
are working is the worst shape a bug can have.
\end{fr}

\begin{fr}
\begin{aibox}
The fix is one argument, and it is worth knowing what it does rather than that
it works. Reducing an array along an axis normally removes that axis:
a $(n, 1)$ summed along its second axis is $(n)$. Asking to keep it leaves
$(n, 1)$, and the difference is exactly the one this section is about.

So \code{keepdims} is not a formatting flag. It is the decision to leave an
axis in place so that the next operation's alignment is stated rather than
inferred \dash{} and the reason it is worth reaching for by default is that a
kept axis of length $1$ can only ever stretch, whereas a missing axis pairs
with whatever happens to be there.
\end{aibox}
\end{fr}

\section{Which of them moves data}
\label{sec:P07-reshape}
\index{tensor!reshape}

\begin{fr}
Three operations change a shape, and they are not the same operation.

\emph{Reshape} keeps the numbers in the order they are and reads them under a
new shape. \emph{Transpose} exchanges two axes. \emph{Permute} reorders all of
them at once, and a transpose is the special case with two.

Section 1 said an array is a buffer, a shape and a rule for turning an index
tuple into a position. Given that, which of the three moves numbers around in
memory?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{In the usual case, none of them.}
Reshape leaves the buffer alone and changes the shape, which is what section 1
made obvious. The surprise is the other one: transposing does not move anything
either. It changes the \emph{rule}, so that the index tuple is turned into a
position a different way round, and hands back the same buffer.

What moves data is asking for the result \emph{contiguous} \dash{} for a fresh
buffer whose order matches its shape \dash{} and that is a third operation with
a name of its own. Program~\ref{prog:P03} priced a pass over memory; this is
where you find out you have asked for one.

\textbf{So \enquote{reshape is cheap and transpose is expensive} is wrong twice
over}, and the reason it is believed is that a transpose is sometimes followed
by a copy that nobody wrote down.
\end{fr}

\begin{fr}
Now the place it costs people a day, and it is exactly where a batch becomes
heads.

You have an array of shape $(b, s, h \times d)$: a batch, a position, and one
long vector per position that is meant to be $h$ heads of $d$ features. It has
to become $(b, h, s, d)$.

Here are two ways to get there. Both produce that shape.

\begin{center}
\code{x.reshape(b, s, h, d).transpose(1, 2)} \\[2pt]
\code{x.reshape(b, h, s, d)}
\end{center}

Do they give the same array?
\dotline
\nextframe
\end{fr}

\begin{fr}
\ans{No.}
On an array of $\val{p07.split.entries}$ entries with
$b = \val{p07.split.b}$, $s = \val{p07.split.s}$, $h = \val{p07.split.h}$ and
$d = \val{p07.split.d}$, the two results differ in
$\val{p07.split.differ}$ of them.

Only the first is right. The buffer runs with $d$ fastest, then $h$, then $s$,
then $b$ \dash{} that is what the shape $(b, s, h \times d)$ says \dash{} so
splitting the last axis into $h$ and $d$ is a relabelling of what is already
there, and the two middle axes then have to be exchanged.

The second asks for the numbers in an order the buffer does not have and gets
it anyway, because reshape does not check anything except the total.
\end{fr}

\mermaidfig{p07-reshape-or-permute}{One run of numbers, two shapes over it, and
what neither of them costs.}{reshape or permute}

\begin{fr}
Which is enough to state a rule, and it is worth trying to state it before
reading it.

Splitting the last axis into two is safe. Merging two neighbours is safe.
Asking for $(b, h, s, d)$ straight out of $(b, s, h \times d)$ is not. Say what
the two safe ones have that the third does not.
\dotline
\nextframe
\end{fr}

\begin{fr}
\begin{ansblock}
A reshape is safe exactly where the axes being split or merged are adjacent and
already in the order the buffer has them.
\end{ansblock}

Anything that would put an axis somewhere it is not needs a permute, and the
permute has to come first. The rule is decidable from the shape and the
operation alone, which is what makes it worth having rather than remembering
which of the two lines above was the right one.

\begin{trapbox}
\textbf{\enquote{Same shape} is not \enquote{same array}, and this is the one
place where the type signature stops helping.}

Program~\ref{prog:P06} made a shape a type signature and a shape error a type
error, which is a strong guarantee and it stops exactly here. Both expressions
above have the type $(b, h, s, d) $. One of them is the heads of your model and
the other is those numbers interleaved.

A type system that cannot tell them apart is not broken \dash{} the two really
do have the same type. What differs is which index means what, and that is
carried in the names you used, in the reshape's order, and nowhere the machine
can read.
\end{trapbox}

\begin{aibox}
Which is the whole of the multi-head split, in a sentence you can now check.

A model computes queries, keys and values as one wide matrix product per
position \dash{} Program~\ref{prog:P06}'s layer, with the batch axis in front.
The heads are not a separate computation: the wide vector is split into $h$
slices of $d$, the head axis is moved in front of the position axis, and what
was one large matrix product becomes $h$ small ones done in parallel.

Then $\code{'bhqd,bhkd->bhqk'}$ contracts the last axis and only the last axis,
so every query position meets every key position, separately for every head and
every batch element. \textbf{Four axes, one contraction, and no step of it is
new.} Program~\ref{prog:P32} assembles the rest.
\end{aibox}
\end{fr}

\begin{fr}
The last frame, and it is about what the notation bought.

Six sections ago an array was a picture with three directions in it and a shape
was bookkeeping. It is an index tuple and a rule, an operation on it is a
statement about which indices meet, and every one of the failures in this
program came from a shape that was legal and not what was meant: a batch index
read as a contraction, a $(n)$ paired with a $(n, 1)$, a reshape asked for an
order the buffer did not have.

\textbf{None of the three is an error, and none of them can be.} The library is
doing exactly what the shapes say. Index notation is how you say what you
meant, and it is why this program spent five frames on a sigma before it typed
anything.

Program~\ref{prog:P08} goes back to two indices and asks a harder question
about them: how much a matrix actually does, which turns out to be a number
smaller than its shape.
\end{fr}

\begin{summarybox}
\sumitem{1--3}{\textbf{An axis is a position in the index tuple, not a
  direction in space.} A shape is a tuple of lengths and the two batch
  conventions \dash{} $k \times n$ and $n \times k$ \dash{} are one map written
  two ways, since $XW\T$ is the transpose of $WX$.}
\sumitem{4--5}{\textbf{Three things are called a dimension} and they answer
  different questions: the number of axes ($\val{p07.emb.rank}$ for a shape of
  $(\val{p07.emb.b}, \val{p07.emb.s}, \val{p07.emb.d})$), the length of one
  axis, and the dimension of the space a stored vector lives in, which is
  $\val{p07.emb.d}$ and is a fact about one axis rather than about the array.}
\sumitem{6--8}{An array's \emph{rank} is its number of axes, which is a
  different word from Program~\ref{prog:P08}'s. Underneath is one buffer of
  $\val{p07.emb.total}$ numbers plus \textbf{a rule turning an index tuple into
  a position}, and section 5 cannot be stated without it.}
\sumitem{9--12}{\textbf{An index that appears twice is summed and an index that
  appears once survives}, so the shape of a result is readable off the letters
  with no arithmetic at all. $\sum_k A_{ik}B_{jk}$ is $AB\T$, and the transpose
  never has to happen.}
\sumitem{13--15}{$S_{bhqk} = \sum_d Q_{bhqd}K_{bhkd}$ is a batched multi-head
  attention score, readable from the rule before any of those words are used.
  \textbf{What decides is the left-hand side}: an index absent from it is
  summed, and one present on it is a batch index however often it repeats.}
\sumitem{16--18}{\textbf{An \code{einsum} string is that sum with the sigma left
  out.} \code{'ik,kj->ij'} is $\sum_k A_{ik}B_{kj}$; the arrow names the
  survivors and everything left of it that is not right of it is summed. So
  \code{'ij->ji'} transposes, \code{'ii->'} is the trace, and
  \code{'ij,j->i'} is a matrix on a vector.}
\sumitem{21--22}{\textbf{\enquote{Repeated means summed} is the rule for the
  sum, not for the string.} In \code{'bij,bjk->bik'} only $j$ is summed;
  $b$ is a batch index because it is on the right too. Dropping it from the
  right is legal, returns the right shape, and adds together results belonging
  to different examples.}
\sumitem{23--25}{\textbf{Broadcasting has an exact rule}: line the shapes up
  from the right, pad the shorter with $1$s, and a pair agrees when the lengths
  match or one is $1$. A $(3)$ added to a $(3,3)$ goes along the rows and a
  $(3,1)$ goes down the columns; both are legal and only one is meant.}
\sumitem{25--29}{\textbf{$(n)$ against $(n,1)$ gives $(n,n)$}, so a loss is
  averaged over every pair, and the excess is exact:
  $2\operatorname{Cov}(p,t)$. At a perfect fit the reported loss is
  $2\operatorname{Var}(t)$ and cannot fall below it. Measured, the reported
  number is $\val{p07.mse.ratio.hi}$ times the true one at a poor fit and
  $\val{p07.mse.ratio.lo}$ times at a good one \dash{} \textbf{the better the
  model, the more it lies}.}
\sumitem{30--32}{\code{keepdims} leaves an axis of length $1$ in place so the
  next alignment is stated rather than inferred. And \textbf{none of reshape,
  transpose and permute moves a number}: each hands back the same buffer with a
  different rule for reading it, and what moves data is asking for the result
  contiguous.}
\sumitem{33--36}{\textbf{Same shape is not same array.}
  \code{x.reshape(b, s, h, d).transpose(1, 2)} and \code{x.reshape(b, h, s, d)}
  both give $(b, h, s, d)$ and differ in $\val{p07.split.differ}$ of
  $\val{p07.split.entries}$ entries. A reshape is safe exactly where the axes
  being split or merged are adjacent and already in the buffer's order.}
\end{summarybox}

\begin{testexercises}
\item An array has shape $(4, 6, 8)$. Give its number of axes, its number of
  entries, and the dimension of the space a stored vector lives in.
  \answerto{Three axes; $4 \times 6 \times 8 = 192$ entries; and the vectors
  have $8$ components, so they live in a space of $8$ dimensions. Three
  different questions and three different numbers.}
\item Say what $\sum_j A_{ij} B_{kj}$ computes, and give the shape of the
  result if $A$ is $m \times n$ and $B$ is $p \times n$.
  \answerto{$AB\T$, of shape $m \times p$. The repeated $j$ is summed and $i$
  and $k$ survive, in that order.}
\item Write the \code{einsum} string for a batch of matrix products, with the
  batch first.
  \answerto{\code{'bij,bjk->bik'}. Only $j$ is summed; $b$ appears on the right
  as well, so it is a batch index rather than a contraction.}
\item Shapes $(5, 1, 4)$ and $(3, 4)$ are combined elementwise. Give the result
  shape, or say why there is none.
  \answerto{$(5, 3, 4)$. Padded to $(1, 3, 4)$, the pairs from the right are
  $4$ with $4$, $1$ with $3$ and $5$ with $1$ \dash{} all three agree, and two
  of them stretch.}
\item Shapes $(5, 4)$ and $(5)$ are combined elementwise. Say what happens.
  \answerto{Refused. Aligned from the right the pairs are $4$ with $5$, which
  is neither equal nor $1$. Writing the second as $(5, 1)$ makes it legal and
  applies it down the columns.}
\item Predictions of shape $(n)$ are compared with targets of shape $(n, 1)$.
  Say what the reported mean squared error is in terms of the true one.
  \answerto{The true one plus $2\operatorname{Cov}(p, t)$, because the
  difference is formed for every pair. At a perfect fit it reads
  $2\operatorname{Var}(t)$ and cannot go lower.}
\item Say why that bug is worse than a bug that reports a random number.
  \answerto{Because the excess is twice a covariance, and a covariance is what
  training increases. It is mild while the model is bad and severe once it is
  good, so it looks like a plateau rather than like a fault.}
\item Say which of reshape, transpose and permute moves numbers in memory, and
  what does.
  \answerto{None of them, in the usual case: each returns the same buffer with
  a different rule for reading it. Asking for the result contiguous is what
  copies, and it is a separate operation.}
\item An array of shape $(b, s, h \times d)$ must become $(b, h, s, d)$. Give
  the operations in order and say why a single reshape will not do.
  \answerto{Split the last axis, giving $(b, s, h, d)$, then exchange the two
  middle axes. A single reshape to $(b, h, s, d)$ asks for the numbers in an
  order the buffer does not have, and gets it, because reshape checks only the
  total.}
\item State the rule that decides when a reshape alone is safe.
  \answerto{When the axes being split or merged are adjacent and already in the
  order the buffer has them. Anything else needs a permute first.}
\end{testexercises}

\begin{furtherproblems}
\item Show that $XW\T$ and $WX$ describe the same layer, using indices.
  \answerto{$(XW\T)_{ij} = \sum_k X_{ik} W_{jk}$ and
  $(WX)_{ji} = \sum_k W_{jk} X_{ik}$, which are the same sum. So one is the
  transpose of the other, and only the axis order differs.}
\item Give the shape of the result of \code{'bhqd,bhkd->bhqk'} in terms of the
  four axis lengths, and say which lengths must agree.
  \answerto{$(b, h, q, k)$. The batch and head lengths must agree between the
  two operands because they are shared, and the feature length $d$ must agree
  because it is contracted. The query and key lengths are free and may differ.}
\item Say what \code{'bij,bjk->ik'} computes, and why it is almost never what
  anybody wants.
  \answerto{The batch products summed over the batch as well, giving one
  matrix. It is legal, has the right shape for a single example, and has added
  together results belonging to different examples \dash{} which is a silent
  fault rather than an error.}
\item Prove the identity
  $\operatorname{mean}_{ij}(p_i - t_j)^2 = \operatorname{mean}_i(p_i - t_i)^2
   + 2\operatorname{Cov}(p, t)$.
  \answerto{Expand both sides. The left is
  $\overline{p^{2}} - 2\bar p\,\bar t + \overline{t^{2}}$, because $i$ and $j$
  run independently; the right is
  $\overline{p^{2}} - 2\overline{pt} + \overline{t^{2}}$ plus
  $2(\overline{pt} - \bar p\,\bar t)$. The two agree term by term.}
\item Say why a kept axis of length $1$ is safer than a missing axis.
  \answerto{A length-$1$ axis can only stretch, so it pairs with whatever is
  opposite it and the intent is written down. A missing axis is padded with a
  $1$ at the front, so it pairs with whichever axis happens to be there, and
  the intent is inferred from the other operand's rank.}
\item An array of shape $(2, 3, 4)$ is reshaped to $(3, 2, 4)$. Say whether
  that is the same as exchanging the first two axes.
  \answerto{No. The reshape keeps the buffer order and relabels it, so the
  entry that was at $(0, 1, k)$ is now at $(0, 1, k)$ read differently; the
  exchange puts it at $(1, 0, k)$. Both give shape $(3, 2, 4)$ and they are
  different arrays.}
\item Say what would have to be true of a type system for it to catch the
  wrong head split.
  \answerto{It would have to carry what each axis \emph{means} and not only how
  long it is \dash{} a shape of $(b, h, s, d)$ with the four names attached
  rather than four numbers. Both expressions have the same shape, so no system
  reasoning about shapes alone can separate them.}
\item Program~\ref{prog:P03} prices a pass over memory. Say which of the
  operations in section 5 incurs one, and when.
  \answerto{Only the request for a contiguous result, and only when the current
  rule for reading the buffer does not already match the shape. A reshape of an
  array that is already contiguous incurs nothing; the same reshape after a
  permute has to copy, because the order it needs is not the order that is
  there.}
\end{furtherproblems}
