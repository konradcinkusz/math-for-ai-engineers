Early draft. The structure, the build, the bilingual tooling and Program F1 in both languages are done — 169 pages in English and 171 in Polish, zero errors, zero overfull vboxes, and a parity check that reports no failures across 56 file pairs. Forty-six of forty-seven programs are stubs carrying the brief they must satisfy. Every ledger is printed on every CI build, so the debt is visible rather than quietly carried.

Why

You can call softmax and you cannot say why it subtracts its own maximum first. You have trained a model and never derived the gradient it was following. You read a paper, understand every sentence around the equations, and skip the equations.

Every book in this field is a second book. Each assumes a floor — algebraic automaticity — that it does not teach and does not test. This one starts at arithmetic and means it, and it uses K. A. Stroud's programmed-learning format, which means it cannot be read. It has to be worked.

What a program looks like

A stream of numbered frames. Nearly every frame ends by asking you for something, and the answer is at the top of the next frame — so you commit before you check. Over one program that happens forty to seventy times.

And it sets traps on purpose. Where a topic has a standard misconception the text walks you into it, lets you commit to the wrong answer, then says flatly that it is wrong. Thirty-eight of them are catalogued, each phrased in the reader's own voice.

Every number is computed, not remembered

A numeric value lives in a script, is written to a generated file, and reaches the page as a reference. The book contains no digits of its own — so a changed number shows up in review as a diff, and CI fails the build when a script no longer produces what the book prints. A few from Program F1:

Ten experiments are specified across the book and none has been run. Until one is, the claim it would support is labelled as judgement and its table stays empty.

Two editions that cannot drift apart

One repository builds both. There is exactly one list of programs, and every user-visible string lives in a language catalogue, so the two editions cannot contain different programs or a label defined in only one of them.

The parity check compares an ordered structural signature, per-frame maths digests, every numeric literal in order and strictly, the two main files' wiring, and — after the build — what the cross-references actually resolved to in each edition.

Where Polish and English usage genuinely differ, the difference is a macro rather than a translator's memory. The rule is the keyboard test: if the reader will type the token, both editions use the code spelling; if they will only read it, the Polish edition uses the Polish form. So tg for the tangent and tanh — not tgh — for the hyperbolic tangent.

Part II comes before the linear algebra, deliberately. Everything after it is arithmetic performed by a finite machine on a budget, and a book that waits four hundred pages to admit the machine cannot represent 0.1 has spent four hundred pages teaching a fiction.

The evidence, and the adverse evidence

Stroud's programs were validated above an 80/80 standard — at least 80% of students scoring at least 80% — and the finding worth having is that the spread narrowed, not that the mean rose. This book has not been read by anybody, so it may not borrow that, and every build prints it as outstanding.

And the general evidence for programmed instruction is adverse: a 1982 meta-analysis found the format did not typically raise achievement in secondary education. That is in the front matter, in a warning box, rather than left out. The defence this book actually makes is narrower — retrieval practice and errorful generation, which is what the frame and the trap are for.

One consequence is stated plainly and should not be softened: the method feels worse than reading while you are doing it. Readers rate the method they retain less from as the more effective one.
