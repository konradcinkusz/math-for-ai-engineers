% ---------- Paper format ----------
% Two formats, chosen by the main file, and the only thing that varies between
% them is this block and the class's point size.
%
%   standard -- 17 x 24 cm at 11pt. The trade format shared with the two
%               companion volumes, so a reader who owns one recognises the
%               second.
%   a4       -- A4 at 12pt. What a reader actually does with this book is read
%               it on a screen or print it on the office printer, and the trade
%               format serves neither: it either sits small in a viewer or
%               lands in the middle of an A4 sheet surrounded by white.
%
% Frames are short, so the measure matters more here than in a prose book: a
% frame that runs past a page turn defeats the cover-the-next-frame discipline
% the whole method rests on. Both formats are therefore set to about the same
% number of characters per line -- A4 spends its extra width on margin, not on
% a longer measure. A 15.5 cm block at 12pt would be some eighty-five
% characters, which is past the point where the eye loses the line return, and
% "it reads badly" would have been fixed into the wrong shape.
% marginparsep and marginparwidth are set here, per format, because the frame
% badge lives in the outer margin and its position must be a declared number
% rather than whatever geometry would have computed. marginparwidth is the
% ceiling on the badge, not its size: the badge is set flush to the text block
% (marginnote's own \raggedrightmarginnote on a recto, \raggedleftmarginnote on
% a verso), so the width only has to be wide enough that a badge can never
% overfull the note's own hbox -- which it CAN. A three-digit badge is 27.89 pt
% at 11 pt and 29.25 pt at 12 pt, both measured; 1.2 cm (34.14 pt) and 1.5 cm
% (42.68 pt) clear that with room.
%
% What this does NOT buy is geometry's own "The marginal notes overrun the
% paper" warning: \Gm@checkmp is called only under \ifGm@verbose and this
% preamble does not pass `verbose'. The \AtBeginDocument assertion below is the
% guard instead, and it is a hard error rather than a warning.
\providecommand{\bookpaper}{standard}
\ifdefstring{\bookpaper}{a4}{%
  \usepackage[
    a4paper,
    inner=3.4cm, outer=2.8cm, top=2.6cm, bottom=3.0cm,
    head=26pt, headsep=0.8cm, footskip=1.4cm,
    marginparsep=6pt, marginparwidth=1.5cm
  ]{geometry}%
}{%
  \usepackage[
    paperwidth=17cm, paperheight=24cm,
    inner=2.2cm, outer=1.8cm, top=2.2cm, bottom=2.4cm,
    head=23pt, headsep=0.7cm, footskip=1.2cm,
    marginparsep=5pt, marginparwidth=1.2cm
  ]{geometry}%
}

% The margin box must fit the NARROWER of the two outer margins, and it must
% fail loudly when it does not. A badge sliced off at the trim produces a green
% log and a mutilated page, so this is an error and not a warning.
\makeatletter
\AtBeginDocument{%
  \begingroup
  \@tempdima=\marginparwidth \advance\@tempdima\marginparsep
  \@tempdimb=\paperwidth \advance\@tempdimb-\textwidth
  \advance\@tempdimb-1in \advance\@tempdimb-\oddsidemargin  % recto outer
  \@tempdimc=1in \advance\@tempdimc\evensidemargin          % verso outer
  \ifdim\@tempdimb<\@tempdimc \@tempdimc=\@tempdimb \fi
  \ifdim\@tempdima>\@tempdimc
    \PackageError{mfabook}{The frame badge does not fit the outer margin}%
      {marginparwidth+marginparsep is \the\@tempdima; the narrower outer
       margin is \the\@tempdimc. Reduce marginparwidth in preamble.tex.}%
  \else
    \wlog{mfabook: margin badge \the\@tempdima\space fits outer margin
          \the\@tempdimc}%
  \fi
  \endgroup}
\makeatother

% ============================================================
%  PROGRAM NUMBERING
%  ---------------------------------------------------------
%  Part F programs are F1..F13; the main programs restart at 1. That is
%  Stroud's scheme and it is worth reproducing, because the Foundation part is
%  explicitly optional and numbering it separately is what makes skipping it
%  feel permitted rather than delinquent.
%
%  \theHchapter is hyperref's *destination* name, and it must stay unique
%  across the whole document. Resetting the chapter counter without also
%  changing \theHchapter produces duplicate PDF destinations, a pile of
%  warnings, and bookmarks that jump to the wrong program.
% ============================================================
\newcommand{\foundationnumbering}{%
  \setcounter{chapter}{0}%
  \renewcommand{\thechapter}{F\arabic{chapter}}%
  \renewcommand{\theHchapter}{F\arabic{chapter}}%
}
\newcommand{\mainnumbering}{%
  \setcounter{chapter}{0}%
  \renewcommand{\thechapter}{\arabic{chapter}}%
  \renewcommand{\theHchapter}{M\arabic{chapter}}%
}

% ============================================================
%  THE PROGRAM KEY, AND THE FRAME RANGE ON THE OPENER
%  ---------------------------------------------------------
%  \mfa@progkey is the key under which everything belonging to the current
%  program is stored -- its outcomes, its "Can you?" rows, its answers, and
%  now its frame total. It must expand to the PRINTED program number
%  (F1, F2, ..., 1, 2, ...), which is what makes an answer findable from the
%  program that owns it. It lives here rather than down with the outcomes
%  because the heading code below needs it too.
%
%  The opener carries the reader's contract: "Frames 1 to 47", in a thin-ruled
%  box at the top right, above everything else. It says how long the
%  commitment is before the reader starts, and in the original it is the first
%  thing on the page (notes/07 section 1). The total counts every PRINTED
%  frame, so it includes the Summary and the Test exercises: those are named
%  frames and carry the last two numbers in the program.
%
%  The total is not known when the opener is typeset, so this is a two-pass
%  mechanism: each program writes its final frame count to the .aux, and the
%  next run reads it back before any of the book is typeset.
%
%  Three things make it robust, and each of them is a bug the obvious version
%  has:
%
%   1. Neither the key nor the count is recomputed at the moment of writing.
%      The key is taken in \program, immediately after \chapter has stepped
%      the counter; the count is taken by every frame. Recomputing either at
%      the flush breaks twice over: \mainnumbering sets the chapter counter
%      back to 0 between Part I and Part II, so \thechapter read at the next
%      \program would expand to "0" rather than to "F13"; and an appendix's
%      \chapter resets frameno, so \value{frameno} read at \end{document}
%      would be 0 rather than the last program's total.
%
%   2. The write happens at the start of the NEXT program and again at
%      \end{document}, because nothing else is common to every program. A
%      written program ends with \furtherproblems and a stub ends with
%      \programstub, so there is no "end of program" marker to hook -- and
%      inventing one would mean editing 94 program files and moving every
%      ordered structural signature the parity check compares.
%
%   3. A program with no frames writes {0}, and a total of 0 prints nothing
%      AND OCCUPIES NO SPACE. That is what separates a stub from a program
%      whose total this run has not computed yet: the stub is a measured zero,
%      and the difference is in the .aux rather than in an author's memory.
%
%  On the first run no total exists yet. The box then prints NOTHING and
%  reserves nothing -- not "??" -- and the run raises a rerun warning instead.
%  46 of the 47 programs are stubs, so a marker here would train the reader of
%  a draft PDF to ignore it, and printing one would move a page boundary
%  between run 1 and run 2 on every opener in the book.
% ============================================================
\makeatletter
\newcommand{\mfa@progkey}{\thechapter}

% Read back from the .aux. One line per program, written by the flush below.
% etoolbox's \csgdef is an unconditional \gdef, so a key written twice in one
% run resolves to the last value rather than raising "already defined".
\newcommand{\mfaframetotal}[2]{\csgdef{mfa@frames@#1}{#2}}

% deliberate: it is what latexmk and rerunfilecheck look for. Writing

\newcommand{\mfa@rangewarn}{%
  \global\let\mfa@rangewarn\relax
  \@latex@warning@no@line{Label(s) may have changed. Rerun for frame ranges}%
}

% Set for the duration of \chapter by \program, and only by \program, so an
% appendix -- which is a \chapter and shares this \titleformat -- does not
% print a frame range it does not have.
%
% THE WHOLE EMISSION IS GUARDED, not just the box's contents. Conditioning only
% the contents means a program with a total of 0 prints no ink but still
% consumes an empty \makebox line plus the 10 pt skip: measured at 27.58 pt
% (trade) and 28.75 pt (A4) of dead space on 46 of the book's 47 openers, with
% no gate able to see it -- no rule is drawn in the gap, no box overflows and
% the page count does not change.
%
% \makebox[\linewidth][r], not \hfill: the title format sets \raggedright,
% whose \rightskip is 0pt plus 1fil, so an \hfill would share the space with it
% and land the box in the middle of the measure rather than at its right edge.
% A box exactly \linewidth wide leaves \rightskip nothing to stretch.
%
% No @ in \mfaopenerbadge's name, and that is load-bearing rather than tidy: a
% \titleformat or \fancyhead argument is tokenised where it is written, so an
% @-name used there outside \makeatletter is read as two tokens and prints its
% own tail.
\newif\ifmfarange
\newif\ifmfa@hasrange
\newcommand{\mfaopenerbadge}{%
  \ifmfarange
    \mfa@hasrangefalse
    \ifcsdef{mfa@frames@\mfa@progkey}{%
      \ifnumgreater{\csuse{mfa@frames@\mfa@progkey}}{0}{\mfa@hasrangetrue}{}%
    }{\mfa@rangewarn}%
    \ifmfa@hasrange
      {\normalfont\normalsize
       \noindent\makebox[\linewidth][r]{%
         \mfa@rangebox{\lblFrameRange{1}{\csuse{mfa@frames@\mfa@progkey}}}%
       }\par}%
      \vspace{10pt}%
    \fi
  \fi
}
\makeatother

% A SECTION HEADING MUST NOT BE THE LAST THING ON A PAGE, and without this it
% very often was. Every numbered section in this book is followed immediately
% by a frame, and \begin{fr} measures the room left and turns the page when a
% frame will not fit. By then the heading has been set. It stays behind, and
% the section it announces begins overleaf.
%
% This was pervasive and nothing saw it: 10, 14, 9 and 9 headings left behind
% in the four builds when it was first measured, in every program from F1 to
% F4. It produces no error, no warning and no overfull box, so it is a defect
% of exactly the class tools/checkpdf.py exists for, and that tool now reads
% the finished PDF for it.
%
% The fix is \begin{fr}'s own room test moved one element earlier: ask for the
% frame's reservation PLUS the heading and its spacing BEFORE the heading is
% set, so the two cannot be separated. \titlespacing gives the heading 24 pt
% above and 9 pt below and it sets at \Large, so a heading that wraps to two
% lines is about four and a half \baselineskip in all.
%
% SWEPT AGAINST tools/checkpdf.py OVER ALL FOUR BUILDS, and, exactly as the
% \begin{fr} reservation does, IT IS NOT MONOTONIC -- a larger reservation
% turns pages earlier and reshuffles every later break:
%
%   reserve   pages en / pl / en-A4 / pl-A4   headings left behind   tails
%   9         284 / 290 / 262 / 264            3                     18
%   10        284 / 290 / 262 / 264            1                     18
%   11        284 / 290 / 260 / 264            0                     16
%   12        284 / 290 / 260 / 264            0                     15   <- chosen
%   13        284 / 290 / 260 / 264            0                     15
%   14        284 / 290 / 260 / 264            0                     15
%   15        284 / 290 / 260 / 264            0                     15
%   16        284 / 290 / 260 / 264            0                     16
%
% Eleven is what the arithmetic above asks for and it clears the headings.
% Twelve is chosen because it also reaches the floor of the orphan-tail count
% (tools/checkpdf.py's fourth check) and costs no page anywhere, which is a
% tie-break and not a reason. SIXTEEN IS THE ROW TO READ before raising this:
% it strands no heading and it puts a tail back, in two builds, while taking
% one out of a third. A larger number is not a safer one.
%
% The table is a measurement of THIS tree on THIS TeX installation. Re-sweep it
% and replace it after any change that moves pages; a sweep table naming a
% constant the code no longer uses reads as evidence and is worse than none.
%
% ONLY NUMBERED SECTIONS. \section* is the Quiz, Can you?, the diagram and
% answer manifests and the front matter; none of those is followed by a frame,
% and the Quiz carries a room test of its own, sized for its own contents.
% Putting this in front of \section* as well would turn pages at the top of
% every program for no gain.
\newlength{\mfasectionroom}
\makeatletter
\newcommand{\mfa@sectionroom}{%
  \par
  \ifdim\pagegoal=\maxdimen\else
    \ifdim\dimexpr\pagegoal-\pagetotal\relax<\mfasectionroom
      \newpage
    \fi
  \fi
}
\let\mfa@plainsection\section
\renewcommand{\section}{%
  \@ifstar{\mfa@plainsection*}{\mfa@sectionroom\mfa@plainsection}%
}
\makeatother

% head=23pt in the geometry options above, not \setlength{\headheight}:
% fancyhdr computes the height it needs from the running-head font and the
% rule, wants 22.5 pt at this size, and silently overprints the top of the text
% block if it does not get it. Setting it through geometry keeps the text block
% where geometry put it instead of pushing it down.
% ---------------------------------------------------------------------------
% CONTENTS: the number boxes are sized for arabic numerals and this book's
% Foundation programs are F1..F13.
%
% book.cls gives a chapter number a 1.5em box and a section number a 2.3em
% box. "F10" does not fit the first and "F10.1" does not fit the second, so
% EVERY entry from F10 onward contributes an overfull hbox -- measured at
% 4.1 pt per chapter line and 1.4 pt per section line, in every build. The
% four chapter boxes were in the book's baseline from the day F10 got a
% number, which is to say they were there before F10 was written and were
% attributed to nothing.
%
% The widths below are measured rather than guessed: \sbox the widest label
% the numbering can produce (\bfseries F13 for a chapter, F13.9 for a
% section) and take the next round em. Do not tighten them without
% re-measuring -- and note that Part II onward numbers programs 1..34, whose
% labels are narrower, so these are the binding cases for the whole book.
\makeatletter

% Mirrored, as the original is (notes/07 section 5): the PAGE NUMBER goes
% OUTER and the RUNNING TITLE goes INNER, both in the head, and the foot is
% empty.
%
% The head carries no frame number. It used to, on the argument that "where am
% I" is a frame question in a book of numbered frames -- which is true, and is
% now answered better by the margin badge on the frame itself. \theframeno at
% shipout is the last frame BEGUN on the page, so the head could name a frame
% that started on the page before; the badge names the frame the reader is
% actually looking at. Measured before it went: trade page 21 carried badges
% 7, 8 and 9 under a head reading "Frame 10".
%
% The page number moves from the foot to the outer head because that is where
% a thumb finds it. Chapter openers keep the class's `plain' style, which puts
% the number at the bottom centre and prints no head -- that is the original's
% treatment too, and it is why the opener's frame-range box is the first thing
% on the page. fancyhdr does not touch `plain', so no \fancyfoot line is
% needed: \fancyhf{} on the line above already cleared the foot.
%
% \mfaheadmark is a WIDTH CAP and it is not optional. Putting the page number
% and a running title on the same line makes them competitors for one measure,
% and fancyhdr does not referee: an over-long field is set at its natural width
% and simply prints on top of the number. It does NOT raise an overfull hbox,
% so neither tools/checklog.py's 15 pt budget nor CI can see it. Measured: with
% frames written into P25, whose English title is 82 characters, the recto head
% ran to x = 430.86 pt while the page number occupied 415.92-430.87 pt -- a
% 15 pt overprint, zero overfull boxes, zero warnings, exit code 0. Seven of
% the manifest's titles are over 50 characters and P25 is over 75 in both
% languages, so this fires the first time anyone writes that program.
%
% The cap measures the box it is given and scales only if it is too wide, so a
% short title is untouched: F1's head is at byte-identical coordinates with and
% without it. It uses \sbox and \resizebox from graphicx, which the preamble
% already loads -- no new package, and no dependence on font metrics.
%
% The 4em reserve is measured at \small, inside the group, so it tracks the
% point size: 40 pt in the trade format at 11pt and 44 pt on A4 at 12pt. A
% three-digit page number is about 15 pt, so the clear gap is 25 pt or more.
\newlength{\mfaheadmax}
\newsavebox{\mfaheadbox}

% ============================================================
%  FRAMES — the unit the whole method is built from
%  ---------------------------------------------------------
%  A program is a stream of numbered frames. Nearly every frame ends by asking
%  the reader for something, and the answer opens the *next* frame, so that the
%  reader can cover what is below and commit to an answer before seeing it.
%
%  The environment is called `fr` rather than `frame` for two reasons. First,
%  \frame is already defined by LaTeX2e (it draws a box in a picture
%  environment) and an environment named `frame` would silently redefine it.
%  Second, this is typed forty to seventy times per program, so it wants to be
%  short in the source.
%
%    \begin{fr}
%    \ans{$x = 3$}            % the answer to the previous frame, optional
%    Teaching text, ending in a question.
%    \end{fr}
% ============================================================

\newcounter{frameno}[chapter]
\renewcommand{\theframeno}{\arabic{frameno}}

% A \label inside a frame needs no help. \newcounter{frameno}[chapter] declares
% a parent, so hyperref composes the anchor from \theHchapter and the book
% already redefines that per numbering scheme: a two-chapter test under
% \foundationnumbering and \mainnumbering produces frameno.F1.1 and
% frameno.M1.1. A \framelabelfix macro used to live here against the theory
% that \theHframeno was undefined and destinations restarted at 1 in every
% program. It was measured and it is false -- the .aux is byte-identical with
% and without it -- and the macro was never called by anything, so it has been
% deleted rather than wired in. Do not reintroduce it.

% The frame number lives in the OUTER margin, in a grey rounded box, and it
% follows the spread: right on a recto, left on a verso. That is what the
% original does (notes/07-stroud-original-layout.md, section 3), and the reason
% is navigational rather than decorative -- a reader thumbing for frame 37 runs
% a finger down the edge of the block and never crosses the text.
%
% The comment this replaces said a margin number "would be the first thing to
% overflow on a 17 cm page". It is not. Badge widths, \bfseries\normalsize,
% measured out of the box register on a TeX Live without newtx (Latin Modern):
%
%          1 digit   2 digits  3 digits
%   11pt   15.30pt   21.59pt   27.89pt
%   12pt   15.75pt   22.50pt   29.25pt
%
% The badge is set flush to the text block -- marginnote's own default is
% \raggedright in the right margin and \raggedleft in the left one -- so the
% clear paper between badge and trim is (outer margin - marginparsep - badge).
% Trade format, outer 1.8 cm = 51.21 pt, two digits: 24.62 pt = 0.87 cm.
% A4, outer 2.8 cm = 79.67 pt, two digits: 51.17 pt = 1.80 cm. Even a
% three-digit badge leaves 0.64 cm in the trade format, and no program in this
% book is planned past seventy frames.
%
% marginnote, not \marginpar. \marginpar goes through the float mechanism and
% takes at most one note per line, deferring the rest -- "Marginpar on page N
% moved" -- and at the four to six frames per page this book runs, that is the
% normal case rather than an edge case. A badge that has been moved down the
% page no longer names the rule it belongs to, which is the one thing this
% element exists to do. \marginnote does not float. It places the note where it
% was issued and takes the page's parity AND the line's x position from the
% .aux, so the badge is right from the SECOND run on; it honours \if@twoside
% and \reversemarginpar, so nothing in this file may set \reversemarginpar.
%
% Loaded [noadjust] deliberately. Under the default [fulladjust], marginnote
% emits a \strut into the line it was called from, which would give the frame
% rule's line the height and depth of a text line. That is usually invisible --
% \baselineskip absorbs it -- but not when the following item is tall enough to
% clamp the interline glue at \lineskip, and \ans opens a tcolorbox immediately
% after the rule in about a third of all frames. Under [noadjust] the note
% rides in a box of zero width, zero height and zero depth. Measured against a
% build with the \marginnote call commented out: every word of main-en landed
% on the same page at the same coordinates, max |dx| and |dy| both 0.000 pt.
% The badge cannot move the text; therefore the page it is recorded on cannot
% change between runs; therefore the side cannot oscillate.
%
% [quiet] because marginnote's default is to log a PackageInfo per note, and a
% finished book has some 2,400 of them.

% The badge is drawn once per distinct frame number and copied thereafter.
% A tikz node is the honest way to get a filled rounded rectangle, but it costs
% about 7 ms. \theframeno restarts at 1 in every program, so a cache keyed on
% the number draws seventy nodes for the whole book rather than 2,415.
% Benchmarked at 2,415 badges: 1.09 s cached, 16.18 s uncached. The cached box
% is context-free -- \normalsize and the palette colours are absolute, not
% relative -- so a copy is always the same badge. About seventy box registers
% are allocated lazily; \newsavebox is global, so allocating inside the body is
% safe.
%
% The fill is `codeframe', the same grey the rule is drawn in, so the badge
% reads as a tab on the rule rather than as a second, competing object.
\makeatletter
\newcommand{\mfa@drawbadge}[1]{%
  \tikz{\node[fill=codeframe, rounded corners=2.5pt,
              inner xsep=4.5pt, inner ysep=2.2pt, outer sep=0pt,
              text=mblue, font=\bfseries\normalsize,
              text height=1.55ex, text depth=0.05ex]{#1};}%
}
% \edef, so the cache key and the digits drawn into it are the same token list
% and cannot drift apart. \theframeno must stay expandable: a robust one makes
% the \csname below fail with "Missing \endcsname inserted" -- loud, and caught
% by tools/checklog.py, but a confusing error there is no reason to invite.
% text height/depth are fixed so that 1 and 45 get boxes of the same height.
\newcommand{\framebadge}{%
  \edef\mfa@bdgn{\theframeno}%
  \expandafter\ifx\csname mfa@bdgbox@\mfa@bdgn\endcsname\relax
    \expandafter\newsavebox\csname mfa@bdgbox@\mfa@bdgn\endcsname
    \expandafter\global\expandafter\sbox
      \csname mfa@bdgbox@\mfa@bdgn\endcsname{\mfa@drawbadge{\mfa@bdgn}}%
  \fi
  \expandafter\copy\csname mfa@bdgbox@\mfa@bdgn\endcsname
}
\makeatother

% The boundary between two frames: a hairline across the measure, with the new
% frame's number in the outer margin beside it.
%
% \marginnote is issued from the rule's own line, in horizontal mode, so that
% the note and the rule share a baseline. That is measured, not assumed: with
% \zsavepos on the rule and on the marginnote body -- OUTSIDE the \raisebox,
% because inside it you measure the raise and not the baseline -- \zposy of the
% two was equal to the scaled point for all 45 frames of F01, at 11 pt and at
% 12 pt, and on both page parities.
%
% The badge is then centred on the rule by measuring its own box, exactly as
% the old on-the-rule badge was, and the formula is unchanged. The rule is
% 0.6 pt tall and sits on the baseline, so its centre is 0.3 pt above it; the
% badge's centre is (\ht-\dp)/2 above its own baseline. Do not replace this
% with a fixed shift: the trade edition sets 11 pt and the A4 edition 12 pt
% from this one source, and a hard-coded shift is right in exactly one of them.
% (The tikzpicture box comes out ht=11.9432pt dp=0pt at 11 pt, so the shift is
% -5.6716 pt there -- it is NOT near zero, and it is not guessable.)
% The list icon that sits on the rule of a Summary frame. It is DRAWN, out of
% three rules, rather than set from a symbol font: pifont, wasysym and the AMS
% symbols are all reachable here, but this preamble already degrades past newtx
% on a thin TeX installation, and an icon that is a picture on one machine and
% a missing-glyph box on another is the one failure this layout cannot absorb.
% Three rules cannot go missing.
%
% Everything is in em, so the glyph scales with the point size: the two formats
% set 11pt and 12pt from this one source and a hard-coded 6 pt icon is right in
% exactly one of them.
\makeatletter
\newcommand{\mfa@listrow}[1]{% #1 = how far this row sits above the baseline
  \rlap{\rule[#1]{0.16em}{0.16em}%
        \kern0.14em
        \rule[\dimexpr#1+0.03em\relax]{0.62em}{0.10em}}%
}
\newcommand{\mfalisticon}{%
  \begingroup\footnotesize

  % A 0.6 pt rule crossing an open glyph reads as a struck-out mark.
  \colorbox{white}{\color{mblue}%
    \mfa@listrow{0.50em}\mfa@listrow{0.25em}\mfa@listrow{0em}%
    \kern0.92em}%
  \endgroup

% The boundary between two frames: a hairline across the measure, with the new
% frame's number in the outer margin beside it, and an optional mark ON the
% rule at its left end.
%
% RECONCILING TWO ELEMENTS. The number used to sit on the left end of the rule
% and the Summary's list icon was specified to sit immediately to its right.
% The number has since moved to the outer margin, so the icon takes over the
% vacated position -- it is a tab on the rule, which is what it was always for.
% It does NOT follow the badge into the margin: \marginparwidth is 34.14 pt in
% the trade format and a two-digit badge plus the icon is about 48 pt, so a
% badge-and-icon margin note would overfull its own hbox. The mark is masked in
% white for the same reason the badge was, and it rides inside a \smash so it
% cannot push the rule down.
%
% \marginnote is issued from the rule's own line, in horizontal mode, so that
% the note and the rule share a baseline. That is measured, not assumed: with
% \zsavepos on the rule and on the marginnote body -- OUTSIDE the \raisebox,
% because inside it you measure the raise and not the baseline -- \zposy of the
% two was equal to the scaled point for all 45 frames of F01, at 11 pt and at
% 12 pt, and on both page parities.
%
% Both the badge and the mark are centred on the rule by measuring their own
% boxes. The rule is 0.6 pt tall and sits on the baseline, so its centre is
% 0.3 pt above it; a box's centre is (\ht-\dp)/2 above its own baseline. Do not
% replace either with a fixed shift: the trade edition sets 11 pt and the A4
% edition 12 pt from this one source, and a hard-coded shift is right in
% exactly one of them. (The badge's tikzpicture box comes out ht=11.9432pt
% dp=0pt at 11 pt, so its shift is -5.6716 pt -- it is NOT near zero.)
%
% \ifblank so that an ordinary frame contributes nothing at all where the mark
% would go, rather than an empty box.
\makeatletter
\newcommand{\mfa@framerule}[1]{%
  \par\penalty-250
  \vspace{\mfaframeabove}%
  \noindent
  \rlap{\textcolor{codeframe}{\rule{\linewidth}{0.6pt}}}%
  \sbox\mfabadgebox{\framebadge}%
  \marginnote{%
    \raisebox{\dimexpr0.3pt-0.5\ht\mfabadgebox+0.5\dp\mfabadgebox\relax}%

  }%
  \ifblank{#1}{}{%
    \sbox\mfamarkbox{#1}%
    \smash{\raisebox{\dimexpr0.3pt-0.5\ht\mfamarkbox+0.5\dp\mfamarkbox\relax}%
                    {\usebox\mfamarkbox}}%
  }%

  \nobreak
}

\makeatother

% The gutter between frames. This is the single most load-bearing number in
% the layout: the frame is the unit the reader covers with a hand, and two
% frames a hairline apart are one block of text to the eye no matter what the
% rule says. Generous above, tighter below, so the white space reads as
% belonging to the frame that follows it rather than floating between the two.
\newlength{\mfaframeabove}
\newlength{\mfaframebelow}
\setlength{\mfaframeabove}{17pt}
% 12 pt, not the 10 pt this was. \mfaframeabove is unchanged and still serves:
% it is the gap that announces a new frame and nothing about it depended on
% where the badge sat. \mfaframebelow did depend on it. The old badge hung off
% the rule's left end and overlapped the gap below, so the boundary read as
% belonging to the frame beneath it and 10 pt was enough. With the badge out of
% the flow the rule is a bare hairline and the frame's first line crowds it.
\setlength{\mfaframebelow}{12pt}

% The room a numbered \section asks for before it will let itself be typeset:
% the frame reservation above, plus the heading and its own spacing. It has to
% be set here and not beside \mfa@sectionroom, because \mfaframeabove and
% \mfaframebelow are declared above and \baselineskip is 0 pt in a preamble --
% the two formats set 11pt and 12pt from this one source, so the constant is
% expressed in \baselineskip and evaluated once the body font exists.
\newcommand{\mfasectionreserve}{12}
\AtBeginDocument{%
  \setlength{\mfasectionroom}{%
    \dimexpr\mfaframeabove+\mfaframebelow
           +\mfasectionreserve\baselineskip\relax}%
}

% it the rule and its margin badge are the last things on the page and the

%

% The answer to the previous frame. Set apart and centred so the eye can find
% the edge to cover, and so a reader who has answered can check in one glance
% without reading on.
% The -4pt that used to sit here pulled the box up under the stranded frame
% badge. The badge is on the rule now, so the box starts where it says it does.
% `unbreakable' must come AFTER `mfa answer': the style carries `breakable'
% from `mfa outlined', and listing the keys the other way round silently
% re-enables breaking. Measured on a forty-paragraph box: [mfa answer,
% unbreakable] sets whole, [unbreakable, mfa answer] splits across two pages.
%
% halign=flush center, not halign=center. `center' stretches the interword and
% maths glue to fill the measure: the frame-11 answer measured 237.68 pt with
% it and 204.20 pt without, a 16% stretch on a line that fits comfortably.
% `flush center' cannot stretch, so an over-wide answer overflows visibly and
% is caught by tools/checklog.py rather than hidden by loose spacing.
\newcommand{\ans}[1]{%
  \par\nobreak
  \begin{tcolorbox}[
    mfa answer, unbreakable,
    left=8pt, right=8pt, top=5pt, bottom=5pt,
    width=0.86\linewidth, center, halign=flush center]
    #1
  \end{tcolorbox}%
  \nobreak\noindent\ignorespaces
}

% A multi-paragraph or worked answer, where a centred box would be wrong.
% `breakable' is restated even though `mfa answer' inherits it, so the
% difference from \ans is legible where a reader of the preamble looks for it.
% Note this also moves ansblock's `before skip' from 0pt to the style's 4pt.
% ansblock is set FULL WIDTH where notes/07 section 3 records the original's
% answer box as narrower than the measure and centred: a multi-paragraph worked
% answer with displayed maths at 0.86\linewidth is where the overfull hboxes
% would come from. The departure is recorded in notes/07.
\newenvironment{ansblock}{%
  \par\nopagebreak
  \begin{tcolorbox}[
    mfa answer, breakable,
    left=10pt, right=10pt, top=6pt, bottom=6pt]
}{%
  \end{tcolorbox}%
  \nopagebreak\par\noindent\ignorespaces
}

% The row of dots. Stroud's signal that the reader is to supply a word, a
% number or an expression. \blank is inline; \dotline occupies its own line,
% which is what a longer derivation step wants.
% \penalty0 offers TeX a break opportunity immediately before the dots. Without
% it the run of dots is glued to the last word of the question, and a long
% question in the Polish edition -- where the words are longer and hyphenate
% less freely -- runs into the margin.
\newcommand{\blank}[1][4em]{\penalty0\makebox[#1]{\dotfill}}
\newcommand{\dotline}{\par\vspace{2pt}\noindent\makebox[\linewidth]{\dotfill}\par\vspace{2pt}}

\newcommand{\yourturn}{%

% The instruction to cover the page and turn over. notes/07 section 3 records
% it as italic, right-aligned, at the end of every frame that has asked the
% reader for a response. It is the sentence that operates the method.
%
% Where it goes is not a judgement call, and check C16 in tools/parity.py
% enforces the rule: a frame has asked for a response exactly when the NEXT
% frame opens by answering it, with \ans or \begin{ansblock}. One cue, last
% thing in the frame, immediately before \end{fr}.
%
% Grey rather than black: the original is monochrome and had only italic to
% work with. This book has colour, so the cue can be furniture and still keep
% the original's italic and its right alignment.
%
% \nopagebreak on BOTH sides of the \vspace. A break at glue is legal only when
% the item before the glue is non-discardable, so the leading penalty is the
% one that forbids a break at the skip itself; the trailing one forbids a break
% between the skip and the cue. Both are wanted -- the cue must not be orphaned
% from the question it belongs to.
%
% The \par must be INSIDE the group: \raggedleft only takes effect on a
% paragraph whose \par is seen while it is in force, and moving the brace one
% token left silently gives a justified, left-aligned line. (\raggedleft also
% zeroes \parindent, which is why no \noindent is needed.)
% NOT set in \color{mgrey}, and it was. This is the instruction to cover the
% page and turn over -- the one sentence the whole method rests on -- and grey
% made it the faintest text on the page. The book's documented colour
% departures from the original are palette choices; greying out an instruction
% is not one of them. The original sets it black italic, and so does this.
%
% AND IT CAN STILL BE ORPHANED. The two \nopagebreak forbid a break at the
% 3pt skip and between that skip and the cue, and they are not enough: what
% ends the page is \dotline's own trailing `\vspace{2pt}`, which is glue after
% a paragraph and therefore a legal breakpoint, and everything this macro
% contributes arrives after it. Measured on the tree that added
% tools/checkpdf.py's orphaned-cue check: three pages across the four builds
% carrying a running head, two italic words and nothing else.
%
% \removelastskip HERE DOES NOT FIX IT, and it is the obvious thing to try.
% Two reasons, either fatal on its own. First, plain \vspace in vertical mode
% is `\vskip#1 \vskip\z@skip`, so \lastskip reads the ZERO skip and the 2pt one
% behind it is untouched. Second and worse, \removelastskip is `\vskip-\lastskip`
% -- on the MAIN vertical list nothing can be taken back, so it cancels the
% space and leaves the breakpoint exactly where it was. Measured: page counts
% and the overfull multiset came back identical in all four builds, and all
% three orphaned cues survived.
%
% RESERVING ROOM AT \dotline DOES CLOSE IT, AND IS NOT WORTH IT. Measured
% during the F6 pass, because it is the one structural candidate the note
% above had not tried: give \dotline the same room test \begin{fr} has,
% sized for the dots plus the cue, and turn the page before the dots when
% there is not enough. The dots and the cue then land at the top of the next
% page, above the answer frame's rule, and the cue is no longer alone.
%
%   reserve   pages (en/pl/en-a4/pl-a4)   orphaned cues   orphan tails
%   none      352 / 358 / 318 / 320             2              35
%   2 bl      354 / 360 / 320 / 322             1              44
%   4 bl      354 / 360 / 320 / 320             0              43
%
% It works and it is a relabelling. Every page the guard turns early is a
% page whose ink stops in its top quarter, which is precisely checkpdf's
% orphan-tail defect -- so two cues become eight more tails and six more
% pages, and the reader still turns over onto white paper. The cue check goes
% quiet because the cue has company, not because the page got better.
%
% So the guard stays the check: the frames are shortened until checkpdf.py is
% clean, and checkpdf.py is what notices when a later program reopens it. Note
% that shortening is not the only editorial move and was not the one that
% worked in F6 -- see CLAUDE.md's F6 pass. When a frame's tail sits one line
% past the boundary, LENGTHENING it can push the whole tail over together,
% where trimming only pulls more of the previous frame up behind it.
\newcommand{\nextframe}{%
  \par\nopagebreak\vspace{3pt}\nopagebreak
  {\raggedleft\itshape\lblNextFrame\par}%
}

% Push the route to the right margin, and if it does not fit on the last line
% of the question, put it on a line of its own -- still at the right margin.
% A bare \hfill cannot do the second half: infinite glue is a legal breakpoint,
% and when the route does not fit TeX breaks there, discards the glue, and sets
% what follows flush LEFT on the next line. Measured: with \hfill a route split
% as "9" on one line and "to 13" flush left on the next.
%
% The \par is BRACED. Without the braces \parfillskip=0pt survives the macro
% and every later paragraph in the same quiz is set fully justified on its last
% line. \teachesat happens to hide that because xstring forces it into a
% \begingroup; \teachesatone has no group, so the leak escaped from it and
% showed up as a justified final line plus an underfull hbox. Setting the
% parameter inside braces and breaking the paragraph inside the same braces is
% the standard idiom and it costs nothing.
%
% It ends the paragraph, so \teachesat must be the last thing typeset in a quiz
% item. \answerto only stores, so it may follow.
\newcommand{\mfa@pushright}[1]{%
  \unskip\nobreak\hfil\penalty50\hskip1em\null\nobreak\hfil
  #1%
  {\parfillskip\z@ \finalhyphendemerits\z@ \par}%
}

% default (2) the real F01 quiz broke 3 + 9 in BOTH A4 builds. 12 was measured:
% 8 keeps the box whole in en-a4 but not pl-a4; 12 and 16 keep it whole in all
% four builds. It is a threshold, not a constant -- a quiz long enough to need
% two pages still breaks, and still loses its heading on the second. That is
% accepted: the original's quiz is one page.
%
% The heading is ordinary content at the top of the box, NOT tcolorbox's
% title / title after break. That variant was built and rejected: the heading
% does repeat on the continuation, and the FIRST part of the box then has no
% top rule at all.

% \section* binds only the first two. Without the room test the heading and its

% The frames that teach the question just asked. Two forms, because a Quiz
% question that routes to a single frame and shows two boxes with "to" between
% them is the kind of small wrongness a reader notices and an author never
% does.
%
% The range is split with xstring rather than with a delimited parameter
% (\def\mfa@teaches#1--#2\@nil). The delimited form works for a literal
% \teachesat{1--7} and for \teachesat{\a--\b}, but an argument with no "--" in
% its token list -- \teachesat{12}, an easy typo for \teachesatone{12} -- runs
% away and dies with "Paragraph ended before \mfa@teaches was complete", which
% names an internal macro and neither the file nor the argument. \IfSubStr
% tests first and \StrCut cannot run away, so a bad argument gets a named
% error at a real file and line, which tools/checklog.py sees.
%
% The SOURCE stays \teachesat{1--7}: splitting it into two arguments would make
% parity's C4 read only the first brace group, so \teachesat{1--9} and
% \teachesat{1--7} would become indistinguishable to the ordered signature.
% The split therefore happens here.
%
% \noexpandarg is set explicitly: xstring's default is full expansion, which
% would try to \edef a protected macro appearing in a range.
%
% \detokenize in the error message, because \PackageError expands its message.
% Without it, \teachesat{\wholerange} reports `was given 5--8, which is not a
% range of the form N--M' -- an error that contradicts itself and sends the
% author looking in the wrong place. \detokenize prints \wholerange.
\makeatletter
\newcommand{\teachesat}[1]{%
  \begingroup\noexpandarg
  \IfSubStr{#1}{--}{%
    \StrCut{#1}{--}{\mfa@rangea}{\mfa@rangeb}%
    \mfa@pushright{%
      \mfa@routecell{\mfa@rangea}%
      \hspace{0.3em}{\footnotesize\color{mgrey}\lblRouteTo}\hspace{0.3em}%
      \mfa@routecell{\mfa@rangeb}}%
  }{%
    \PackageError{mfa}{\string\teachesat\space found no `--' in its argument
      `\detokenize{#1}'}{A route must be a literal N--M range. Write
      \string\teachesatone{N} for a single frame; if the ends come from macros,
      write them either side of the dashes.}%
  }%
  \endgroup
}
\newcommand{\teachesatone}[1]{\mfa@pushright{\mfa@routecell{#1}}}
\makeatother

% ---- Summary --------------------------------------------------------------
% Every item carries the frame number it came from, in square brackets. That
% is the eighth-edition improvement and it is the single cheapest thing in the
% format: it turns a summary into a return index, so a reader who fails one
% line of "Can you?" knows exactly which four frames to reread.
\makeatletter
% The heading of a closing part of a program -- Summary, Can you?, Test
% exercises, Further problems. One size for all four, one step below the
% numbered topic heads inside the program: those are what the reader is
% reading, these are what they are checking with.
%
% The heading is typeset BEFORE the contents line is written, which is the
% order \section* uses and the order that gets the page number right. The
% \write is contributed to whichever page it lands on, so writing it first
% records the page the heading was going to start on rather than the page it
% actually starts on -- and the two differ by exactly one whenever the heading
% begins a page.
\newcommand{\mfa@endhead}[1]{%
  {\noindent\large\bfseries\color{mblue}#1\par}%
  \phantomsection\addcontentsline{toc}{section}{#1}%
  \nobreak\vspace{7pt}\nobreak
}

% A named frame must not open at the foot of a page. WITHOUT THIS GUARD the
% frame rule, the badge, the icon and the heading are stranded at the bottom of
% a page and the panel begins overleaf. Reproduced at 2 of 26 vertical
% positions in the trade format and 2 of 26 on A4; the same sweep against the
% unpatched preamble strands nothing, 0 of 26 in both. \nobreak is not enough:
% it binds the heading to the GLUE that follows it, but a breakable tcolorbox
% splits itself in its own code, measures the room left and is perfectly
% willing to contribute an empty first piece. This is the one service \section*
% was performing here for free, through \@startsection's penalty before the
% heading, and it stopped being free the moment the heading stopped being a
% \section.
%
% needspace's stretch-and-penalty trick does NOT fix it, and it was tried
% first: it relies on TeX's page builder finding the page overfull and
% preferring an earlier breakpoint, and on a rigid page every candidate is
% equally awful, so TeX keeps the material and lets tcolorbox split anyway.
% Measured: 95pt reserved against 54pt left, heading still stranded.
%
% So the room is measured and the page is turned explicitly. \pagegoal is
% \maxdimen on a page with nothing on it yet, which means "unlimited" and not
% "no room"; testing it the obvious way turns a page at the top of every
% program. Six \baselineskip is heading plus three lines of panel, and it is
% expressed in \baselineskip rather than in points because the two formats set
% 11pt and 12pt from this one source.
\newcommand{\mfa@namedframe}[2]{% #1 = mark on the rule, #2 = heading
  \par
  \ifdim\pagegoal=\maxdimen\else
    \ifdim\dimexpr\pagegoal-\pagetotal\relax<%
          \dimexpr\mfaframeabove+\mfaframebelow+6\baselineskip\relax
      \newpage
    \fi
  \fi
  \refstepcounter{frameno}%
  % A named frame counts towards the opener's range like any other: the reader
  % sees frames 46 and 47, so "Frames 1 to 45" on the opener would be a lie.
  \mfa@noteframe
  \mfa@framerule{#1}%
  \mfa@endhead{#2}%
}

% The continuation mark: a triangle at the bottom right of every piece of a
% broken panel except the last. `overlay first and middle` is the exact key --
% `overlay broken` would mark the last piece too and `overlay` would mark a
% panel that never broke at all, and both are lies to a reader who is being
% told whether to turn the page. Drawn rather than set from a font, for the
% reason \mfalisticon is.
%
% The coordinates keep the whole mark inside the panel's padding, and that is
% arithmetic rather than taste. The triangle spans 5pt horizontally and 5.2pt
% vertically from its apex; the panel pads 8pt right and 6pt bottom. So the
% apex may sit at most 3pt from frame.east (3+5 = 8) and its vertical centre at
% most 3.4pt above frame.south (3.4+2.6 = 6). The obvious xshift=-7pt,
% yshift=4.5pt reaches 12pt into a right padding of 8pt and 7.1pt into a bottom
% padding of 6pt -- i.e. into the text column, where the descender of a
% justified last line lives.
\newcommand{\mfacontinuationmark}{%
  \path[fill=mblue]
    ([xshift=-3pt,yshift=3pt]frame.south east) --
    ++(-5pt,2.6pt) -- ++(0pt,-5.2pt) -- cycle;%
}
\makeatother

% ---- The contents column, and a four-digit page number ----------------------
% book.cls reserves \@pnumwidth = 1.55em for a contents entry's page number and
% \@tocrmarg = 2.55em for the right margin the title wraps against. Both fit
% three digits and neither fits four: measured, "1001" and "1009" each overflow
% by 4.93 pt in main-pl, which crossed a thousand pages in the P22 pass and
% acquired four-digit entries in the P23 one.
%
% It is the contents column's THIRD defect of this shape, after P16's long
% Polish title and the running head \mfaheadmark guards -- and unlike those two
% it cannot be fixed by shortening anything, because the overflowing token is a
% page number. Every remaining program pushes more entries past 999, so this is
% widened once rather than watched.
%
% MEASURED, not guessed: 1.55em is 16.97 pt at the contents font's 10.95 pt and
% the complaint is 4.93 pt, so four digits need 21.90 pt, which is 2.0em.
%
% \@tocrmarg IS DELIBERATELY NOT CHANGED, and that is the whole of what was
% learnt here. It sets the right margin every \@dottedtocline entry wraps
% against, and the diagram manifest is such a list -- \mermaidfig writes its
% description through \addcontentsline{dgm}{subsection} -- so the two share it.
% Widening it to 3.2em to keep the old gap narrowed that description column by
% 0.65em and put a box back in ALL FOUR builds, in the one column this book has
% already overflowed five times. The page-number box grows into the 1em gap
% between the two lengths instead, which is where the room actually is, and no
% wrap point moves.
%
% \emergencystretch is the second half, and the FIRST attempt at it was worse
% than the defect. \l@part and \l@chapter take their title's rightskip from
% \@pnumwidth as well, so widening it narrows those two lines by 0.5em --
% enough to tip the Polish Part V title over on A4. Last-resort stretch is the
% right instrument for that: TeX spends it only on a line it cannot otherwise
% set, and a long part title running to two contents lines is ordinary.
%
% BUT IT WAS APPENDED TO \tableofcontents, WHICH IS AFTER \@starttoc{toc} HAS
% ALREADY TYPESET THE WHOLE CONTENTS. So it reached nothing it was written for
% and instead leaked into every paragraph of the book from the contents page
% onward -- \tableofcontents is not inside a group, so the assignment simply
% stood. It was invisible in the ledgers because it made them look BETTER: the
% 6.3 pt box this file records in main-en-a4 disappeared, which is a genuine
% overfull line silently loosened rather than fixed, and is exactly the
% objection this preamble makes to \vfuzz two thousand lines below.
%
% \pretocmd sets it before the contents is read and \apptocmd puts it back
% after, so it is scoped to the one region that needs it and to nothing else.
% Restore to 0pt rather than to a saved value: LaTeX's own default is 0pt and
% nothing else in this preamble sets it.
\makeatletter
\renewcommand{\@pnumwidth}{2.05em}
\makeatother
\pretocmd{\tableofcontents}{\emergencystretch=12pt\relax}{}{%
  \PackageWarning{mfabook}{Could not patch tableofcontents for emergencystretch}}
\apptocmd{\tableofcontents}{\emergencystretch=0pt\relax}{}{%
  \PackageWarning{mfabook}{Could not restore emergencystretch after contents}}

% ---- The programs register -------------------------------------------------
% \program{Title} opens a program: it is \chapter plus the bookkeeping that
% lets the back matter reproduce this program's answers under its own name.
\makeatletter
% The optional argument is a SHORT title, and it exists because the table of
% contents is a narrow column and this book's titles are getting longer. P16's
% Polish title overflowed the contents line by 2.2 pt, which is the same class
% of defect as the diagram manifest's column and as the running head that
% \mfaheadmark guards -- and the note on \mfaheadmark already said this one
% was latent and waiting for a long-titled program. It is LaTeX's own
% \chapter[short]{long}, passed through, rather than anything invented here.
% USE IT IN BOTH EDITIONS OR IN NEITHER: parity compares the two files'
% structural tokens, so a short form in one and not the other diverges.
\newcommand{\program}[2][]{%
  % The previous program's frame total, written now because this is the first
  % moment at which that program is certainly over. \AtEndDocument catches the
  % last one.
  \mfa@flushframetotal
  \mfarangetrue
  \def\mfa@shorttitle{#1}%
  \ifx\mfa@shorttitle\@empty \chapter{#2}\else \chapter[#1]{#2}\fi
  \mfarangefalse
  % The key for the program just opened, captured here and not recomputed at
  % the flush: \mainnumbering resets the chapter counter between Part I and
  % Part II, so \thechapter read at the next \program would expand to "0".
  % Zero is the honest starting count -- a program with no frames writes it,
  % which is what lets the opener tell a stub from a first run.
  \xdef\mfa@lastprog{\mfa@progkey}%
  \gdef\mfa@lastcount{0}%
  \csgdef{mfa@title@\thechapter}{#2}%
  % Expanded, for the same reason as the answer keys above.
  \listxadd{\mfaprograms}{\thechapter}%
}
\newcommand{\mfa@printoneanswer}[2]{% #1 program key, #2 item key
  \item[\textbf{#2}] \csuse{mfa@a@#1@#2}%
}
\newcommand{\mfa@answerprogram}[1]{%
  % PURE SHRINK before the heading, and it is load-bearing rather than
  % cosmetic: 0 pt natural, so nothing moves, and 3 pt a block for TeX to give
  % back when a page will not otherwise fit.
  %
  % It is here rather than on the list below because of where the failure
  % actually was. Every UNWRITTEN program still gets a heading and a one-line
  % "no answers were stored", so the tail of this appendix is twenty-two
  % heading-plus-line units in a row -- eleven on one page -- and those pages
  % contain no list at all. \subsection* binds its heading to what follows with
  % \@startsection's penalty and offers about 0.2ex of shrink, so the page was
  % a concertina of rigid three-line blocks: eleven legal breakpoints and
  % nothing to give at any of them. \raggedbottom cannot help, because it adds
  % stretch and the page is too TALL.
  %
  % The tell was that adding shrink to the list lengths moved the reported
  % overflow by not one tenth of a point. Shrink has to be where the material
  % is, and on those pages the material is headings.
  \par\vspace{0pt plus 0pt minus 3pt}%
  \subsection*{\lblProgram~#1\quad\textmd{\itshape\csuse{mfa@title@#1}}}%
  \ifcsdef{mfa@akeys@#1}{%
    % The three list lengths below carry SHRINK, and that is not cosmetic --
    % see the note above \answersbody. Rigid, they made a page of answers a
    % block of matter that could give back nothing at all.
    \begin{list}{}{%
      \setlength{\leftmargin}{3.2em}\setlength{\labelwidth}{2.7em}%
      \setlength{\labelsep}{0.5em}%
      \setlength{\itemsep}{3pt plus 0pt minus 1pt}%
      \setlength{\topsep}{3pt plus 0pt minus 1pt}%
      \setlength{\parsep}{0pt plus 0pt minus 0.3pt}%
      \renewcommand{\makelabel}[1]{\hfill##1}}
      \forlistcsloop{\mfa@printoneanswer{#1}}{mfa@akeys@#1}
    \end{list}%
  }{%
    \par\noindent{\color{mred}\lblNoAnswers}\par
  }%
}
% The answers body, without a heading of its own, so the appendix that carries
% it can be a numbered appendix like any other and appear in the running heads
% and the ToC in the ordinary way.
%
% \raggedbottom, and it is the index's cure arriving in the second place that
% needed it. CI failed `en` A4 on TWO overfull vboxes on ONE page, 12.3 pt and
% 5.0 pt, deep in this appendix, on source that builds with zero vboxes in the
% container that writes the published PDF -- the divergence this file already
% documents, where CI has newtx and this container has not and cannot install
% it. It was located by page number rather than guessed at: tools/checklog.py
% now prints the page each box landed on, for exactly this reason.
%
% The defect is structural and it was latent rather than new. A page of
% answers is a `list` whose \topsep, \itemsep and \parsep were all set with
% \setlength and were therefore RIGID, under book's twoside \flushbottom,
% which requires every page to be exactly \textheight tall. So the page had
% almost no glue to give: \subsection*'s own skip carries about 0.2ex of
% shrink and nothing else did. Adding fifteen answers anywhere in the book
% moves every later page, and one of them then landed 12.3 pt over with no
% way to absorb it.
%
% Answers are reference matter, like an index: nobody reads them front to
% back, and every answers section in every textbook lets its pages end short.
% So the same two-part cure the index needed applies unchanged, and for the
% same reason -- \raggedbottom lets a page end short, and the SHRINK on the
% list lengths absorbs a residual that raggedbottom cannot, because
% raggedbottom adds stretch and an overfull page is too TALL rather than too
% short.
%
% Scoped to this appendix, so no frame, no cue, no orphan tail and no page in
% the body of the book moves; \clearpage flushes the last answers page before
% \flushbottom resumes for everything after it. \vfuzz was rejected here for
% the reason it was rejected for the index: it hides real overfull vboxes
% everywhere else, which is how a gate goes quiet.

  \raggedbottom
  \noindent\lblAnswersIntro\par\vspace{8pt}
  \ifdef{\mfaprograms}{\forlistloop{\mfa@answerprogram}{\mfaprograms}}{%
    \noindent{\color{mred}\lblNoAnswers}\par}%
  \clearpage\flushbottom
}

% Two shared styles, so the eight boxes below carry one set of spacing numbers
% between them rather than eight copies that drift apart. `before skip` and
% `after skip` are the point of this: tcolorbox's defaults are a couple of
% points, which is not enough air to read as a separate block, and every box
% having its own value is how a page ends up looking arbitrary.
%
% \emph{tinted} is a block the reader may read in passing -- a tint and a thick
% left bar, no outline. \emph{outlined} is a block the reader must stop at, and
% it gets a full rule on white. That is the whole visual grammar; a third
% treatment would mean the first two are not carrying their meaning.
\tcbset{
  mfa tinted/.style={
    enhanced, breakable, sharp corners,
    boxrule=0pt, leftrule=3.5pt,
    left=10pt, right=10pt, top=7pt, bottom=7pt,
    before skip=13pt, after skip=13pt,
    fonttitle=\bfseries\small,
  },
  mfa outlined/.style={
    enhanced, breakable, sharp corners,
    boxrule=0.8pt,
    left=10pt, right=10pt, top=7pt, bottom=7pt,
    before skip=13pt, after skip=13pt,
    fonttitle=\bfseries\small,
  },
  % The answer to the previous frame. It is the OUTLINED treatment -- a rule on
  % white, the thing the reader must stop at -- declared as that style plus its
  % deviations rather than as a third one, so the padding and the corner
  % treatment cannot drift away from the admonitions.
  %
  % Three deviations, each with a reason:
  %
  %   boxrule 0.8 -> 0.6pt. The page then carries exactly two rule weights:
  %     0.6pt for frame furniture (\framerule and this box) and 0.8pt for
  %     content the author flagged (the admonitions). The answer box appears
  %     about thirty times per program against an admonition's four or five,
  %     so it is the one that has to be quiet.
  %
  %   colback mfaint -> white. mfaint is FBFCFD -- nearly white, and at that
  %     distance from the paper it reads as a smudge rather than as a tint.
  %     notes/07 section 3: "white inside, narrower than the measure, centred".
  %
  %   before skip 13pt -> 4pt. This box almost always sits directly under
  %     \framerule, which has already laid down \mfaframebelow, so the
  %     effective gap is that plus 4pt rather than 4pt. 13pt on top of it would
  %     read as a gap rather than as an opening.
  mfa answer/.style={
    mfa outlined,
    boxrule=0.6pt,
    colback=white, colframe=mgreen,
    before skip=4pt, after skip=10pt,
  },
}

% A terminal transcript written by a script under code/ and pulled in whole.
%
% There is no in-source form of this and there must not be. \val{} does not
% expand inside a verbatim body -- it prints the macro name -- so a transcript
% typed into a program is a transcript that cannot quote a computed value, and
% a transcript nobody ran is indistinguishable on the page from one that was.
% The sibling volume's only outright factual error survived a whole draft
% inside a fabricated console block for exactly that reason.
%
% ONE file serves both editions. Listing comments stay English by standing
% rule, so the transcript contributes no digits to either program's source and
% C12's strict numeric comparison stays green. The consequence is that parity's
% C13 cannot see the file at all -- VERB_ENV_RE scans in-source environments --
% so the ASCII rule is asserted by the script that writes it.
%
% AND IT MUST SURVIVE THE FILE BEING ABSENT. figures/transcripts is written by
% `make numbers`, exactly as figures/values is, so a clean checkout that has
% not run it has no transcript -- and \lstinputlisting on a missing file is a
% fatal `File not found`, which killed the text-only draft build that the rest
% of this preamble goes to some trouble to keep working. \mermaidfig has had
% this fallback since the diagrams pipeline was written; \transcript shipped
% without it and had the same exposure. Same contract: print a visible marker
% where the missing thing belongs, and build.
%
% THE ARGUMENT IS A STEM, NOT A PATH, and that is a correction rather than a
% preference. This macro used to take the whole path, and nine of the twelve
% call sites in the book passed a stem instead -- so \IfFileExists looked for
% `p06-order.tex`, failed, and printed the marker. TEN OF THE TWELVE
% TRANSCRIPTS IN THE BOOK HAD NEVER REACHED A PAGE, through nine programs and
% every gate green, because the fallback that keeps a clean checkout building
% also makes a typo look deliberate: the marker prints in grey with a label and
% reads as somebody's decision.
%
% Taking the stem makes the wrong call impossible rather than detectable, which
% is the same move \mermaidfig and \pyregion already make. The detection is
% kept as well -- tools/check_structure.py fails on a \transcript naming a
% file that is not there, before the build rather than after it, because on a
% tree where `make numbers` has run the marker means a typo and nothing else.
\newcommand{\transcript}[1]{%
  \par\smallskip
  \IfFileExists{figures/transcripts/#1.txt}{%
    \lstinputlisting[style=mfacode, numbers=none,
                     basicstyle=\ttfamily\scriptsize,
                     keywordstyle=\color{black},
                     backgroundcolor=\color{white}]{figures/transcripts/#1.txt}%
  }{%
    \begin{tcolorbox}[
      enhanced, breakable, width=\linewidth, sharp corners,
      colback=white, colframe=mgrey, boxrule=0.8pt,
      left=8pt, right=8pt, top=8pt, bottom=8pt]
      {\bfseries\color{mgrey}\small \lblTranscriptMissing}\\[4pt]
      {\ttfamily\scriptsize\color{mgrey} \detokenize{#1}}%
    \end{tcolorbox}%
  }%
  \par\smallskip
}

% ============================================================
%  COMPUTED VALUES
%  ---------------------------------------------------------
%  The house rule in the sibling books is "run the listing, or mark it". The
%  analogue here is stronger, because a wrong digit in a maths book is not a
%  broken example, it is a lie the reader will carry.
%
%  Every number that came out of a computation is written by a script under
%  code/ into figures/values/<program>.tex as
%
%      \mfaval{f01.eps64}{2.220446049250313e-16}
%
%  and pulled into the text with \val{f01.eps64}. The script is the source of
%  truth; the book cannot disagree with it, because the book does not contain
%  the digits. A value the scripts no longer produce prints a visible marker
%  and is counted by `make debt`.
%
%  \val also applies the locale's decimal separator, which is how the Polish
%  edition gets its decimal comma without a translator having to remember.
% ============================================================
\IfFileExists{siunitx.sty}{%
  \usepackage{siunitx}%
  \sisetup{
    group-digits = integer,
    group-minimum-digits = 5,
    group-separator = {\,},
    exponent-product = \cdot,
    output-decimal-marker = {\mfadecimalmarker}
  }%
  \newcommand{\mfanum}[1]{\num{##1}}%
}{%
  \newcommand{\mfanum}[1]{##1}%
}

\makeatletter
\newcommand{\mfaval}[2]{\csgdef{mfaval@#1}{#2}\listxadd{\mfavalues}{#1}}
% \num on a non-numeric body is a FATAL siunitx error -- "Invalid number" --
% and under -halt-on-error that is the whole build. A script emitting a word
% where the book expected a number is a plausible mistake.
%
% The check is NOT done here. Deciding in TeX whether a token list is a number
% means parsing it character by character, which is fragile and was got wrong
% once already. The generator knows the answer for free, so it emits \mfaval
% for a number and \mfavaltext for a word, and this end only has to enforce
% which macro reads which.
\newcommand{\val}[1]{%
  \ifcsdef{mfaval@#1}{%
    \ifcsdef{mfavaltext@#1}{%
      \PackageError{mfabook}{Value `#1' is not a number}%
        {\string\val\space passes its body to siunitx, which refuses anything
         that is not a number. Use \string\valtext{#1} instead, or fix the
         script in code/ that emits this key.}%
    }{}%
    \mfanum{\csuse{mfaval@#1}}%
  }{\textcolor{mred}{\textbf{[?\,#1]}}}%
}
% A value that is deliberately a word rather than a number -- a format name, a
% verdict, a unit. Rare, and a visibly different macro so nobody reaches for
% \val and gets an error they cannot place.
\newcommand{\valtext}[1]{%
  \ifcsdef{mfaval@#1}{\csuse{mfaval@#1}}%
    {\textcolor{mred}{\textbf{[?\,#1]}}}%
}
\newcommand{\mfavaltext}[2]{%
  \csgdef{mfaval@#1}{#2}\csgdef{mfavaltext@#1}{}\listxadd{\mfavalues}{#1}%
}

  \@starttoc{dgm}%

\newcommand{\mermaidfig}[3]{%
  \addcontentsline{dgm}{subsection}{\protect\numberline{}\texttt{#1.mmd} --- #3}%
  \IfFileExists{figures/diagrams/\booklang/#1.pdf}{%
    \begin{figure}[htbp]
    \centering
    \includegraphics[width=0.95\linewidth,height=0.42\textheight,keepaspectratio]{figures/diagrams/\booklang/#1.pdf}%
    \caption{#2}\label{fig:#1}
    \end{figure}%
  }{%
    % The unrendered case deliberately does NOT float. A Mermaid source
    % typeset verbatim is often taller than a page, and a float cannot break,
    % so wrapping it in `figure` produces an overfull box per diagram and a
    % pile of tcolorbox warnings. In the flow it breaks like any other text.
    \par\medskip
    \begin{tcolorbox}[
      enhanced, breakable, width=\linewidth, sharp corners,
      colback=white, colframe=mgrey, boxrule=0.8pt,
      left=8pt, right=8pt, top=8pt, bottom=8pt]
      {\bfseries\color{mgrey}\small \lblNotRendered}\\[4pt]
      {\ttfamily\scriptsize\color{mgrey} figures/mermaid/\booklang/#1.mmd}\\[6pt]
      \IfFileExists{figures/mermaid/\booklang/#1.mmd}{%
        % ASCII only, like every other listing in this book: the fallback runs
        % the Mermaid source through `listings`, which aborts on a multi-byte
        % character it has no literate mapping for.
        \lstinputlisting[style=mfacode,numbers=none,basicstyle=\ttfamily\scriptsize,
                         backgroundcolor=\color{mlight},frame=none,
                         keywordstyle=\color{black}]{figures/mermaid/\booklang/#1.mmd}%
      }{%
        {\small\color{mred} \lblSourceMissing: \texttt{figures/mermaid/\booklang/#1.mmd}}%
      }%
    \end{tcolorbox}%
    \captionof{figure}{#2}\label{fig:#1}
    \par\medskip
  }%
}

% A bare \log is FORBIDDEN in this book. TWO things enforce that, and neither
% is the tool this comment used to name -- there is no tools/check_notation.py
% and there never was. What exists is parity.py's C10, which fails on a bare
% \log with a file and a line before the build is run, and the \PackageError
% below, which fails the run itself. Note what the second one does NOT do:
% under -interaction=nonstopmode it writes a PDF over the top of the error, so
% the artefact is not the evidence -- tools/checklog.py is, and it reports the
% error the log's own `!`-less, -file-line-error form hides.
%
% In Polish textbooks \log means base ten; in machine-learning
% writing it means base e. The same three characters carry opposite meanings to
% the two readerships this book serves, and they collide hardest in exactly the
% programs where it matters most -- entropy in bits and cross-entropy in nats
% are two programs apart. Write \ln for nats and \logb{2} for bits. It costs
% two characters and removes the ambiguity entirely.
\makeatletter
\let\mfa@origlog\log
\renewcommand{\log}{%
  \PackageError{mfabook}{A bare \string\log\space is forbidden in this book}%
    {Write \string\ln\space for natural logarithms or \string\logb{2}\space for
     bits. The base is never left to a convention here; see Appendix B.}%
  \mfa@origlog}
% The one legitimate form: an explicit base.
\newcommand{\logb}[1]{\mathop{\mfa@origlog}\nolimits_{#1}}
% ...and a way to write the forbidden thing where the base is genuinely absent.
% Two kinds of place, and both are stated as rules rather than counted:
%
%   * where the ban ITSELF is the subject -- Appendix B, which states the
%     convention, and F03's entry Quiz and section 2, which teach it. The trap
%     frame prints a bare logarithm with no base and asks the reader to write
%     down its value, because the two readerships answer that confidently and
%     differently.
%   * INSIDE AN O, THETA OR OMEGA, which is P03's whole subject. There the
%     omission is a theorem rather than a convention: log_a n = log_b n / log_b a,
%     so changing the base multiplies by a constant, and a constant is exactly
%     what the notation discards. O(n log n) therefore names ONE class for every
%     base, and writing a base inside it would suggest a distinction that does
%     not exist. P03 has a notation box saying so.
%
% Nowhere else.
%
% The COUNT is deliberately not stated here. It was, as "once", and it was
% wrong by five in F03 alone -- a claim the book made about itself in three
% places at the same time, and one that nothing could check, because C10's
% regex cannot see inside this macro name. The restriction is a convention and
% not a gate; record it as a rule, never as a tally nobody maintains.
\newcommand{\mfalogplain}{\mathop{\mfa@origlog}\nolimits}
\makeatother

% ============================================================
%  INDEX
%  ---------------------------------------------------------
%  Two-column, and its entries include \texttt{} names that do not hyphenate.
%  Ragged right keeps multi-word entries off the margin; it cannot help a
%  single token wider than the column, so keep verbatim index entries under
%  about 29 characters and index longer names by concept instead. Both sibling
%  books learned this the same way.
% ============================================================
%  And RAGGED BOTTOM, added after CI failed on two OVERFULL VBOXES in the
%  index -- 3.8 pt and 17.4 pt -- while this container built the same source
%  clean. That is the metric split this file already records in both its other
%  directions, and it is the worst of the three, because the index is the one
%  place where the material is nearly rigid: index lines carry no stretch,
%  \parskip here is 0pt plus 0.3pt with NO shrink, and \indexspace gives back
%  only 3 pt. `book` in twoside mode sets \flushbottom, so every column is
%  held to the full text height with almost nothing to give.
%
%  \raggedbottom lets a column end short, which is what every index in print
%  does, and removes the pressure that forces the choice between a badly
%  underfull column and an overfull one. It also silences the hundreds of
%  "Underfull \vbox ... while \output is active" lines the index contributes.
%
%  HONESTLY: this could NOT be reproduced here. newtx and inconsolata were
%  installed to try, and the container's TeX Live is three years behind CI's,
%  so the metrics still would not have matched -- and leaving them installed
%  would have broken the very split that makes this container useful (it is
%  the bare installation that found the upquote defect). They were removed
%  again. CI is the reproduction, and if this does not clear it, the next step
%  is to look for what in the index cannot be broken, not to trim an entry
%  until the number goes away.
%
%  AND A LITTLE SHRINK, added after \raggedbottom alone took CI from
%  [17.4, 3.8] to [3.8, 3.8]. The two remaining boxes are the SAME size, which
%  is the tell: \output fires once per column in a \twocolumn region, so that
%  is one page overflowing identically in both columns -- the index's first,
%  where \@makeschapterhead leaves a residual height that is not a whole
%  number of lines. \raggedbottom cannot help, because it adds STRETCH and the
%  page is too tall rather than too short.
%
%  What an index lacks is shrink. `theindex` sets \parskip to 0pt plus 0.3pt
%  with none, so a column of forty entries can give back nothing at all and
%  TeX's only options are an overfull column or a worse break. A fifth of a
%  point of shrink per entry is eight points per column, absorbs the residual
%  under any metrics, and is invisible: it is a fraction of a point between two
%  index lines. \vfuzz was the other candidate and was rejected -- raising it
%  hides real overfull vboxes everywhere else, which is how a gate goes quiet.
%  (Written with plain lengths, not \z@ and \@plus: this block sits OUTSIDE
%  the \makeatletter group above, and an @-command here is an undefined
%  control sequence in every build.)
%
%  AND IT CAME BACK, at 0.2 pt of shrink, when Program P12 added its index
%  entries: CI reported 12.29 pt and 4.99 pt on ONE page of `main-en-a4.ind`,
%  which is again the two columns of a single page. A fifth of a point over a
%  column of forty entries is about eight points, and eight points does not
%  absorb twelve. Half a point does -- about twenty a column -- and it is
%  still half a point between two index lines, which is nothing. The number
%  scales with the index and the index only grows, so expect to raise it
%  again; \vfuzz stays rejected for the reason above.
%
%  AND IT CAME BACK AGAIN, exactly as the line above said it would, when
%  Program P15 added its entries: 5.5 pt on the fourth page of `main-pl.ind`,
%  on THIS container rather than on CI, which is the same defect arriving
%  from the other machine. Half a point was about twenty a column and the
%  index is now longer than that covers. Nine tenths of a point is about
%  thirty-six a column, which leaves room for several more programs, and it
%  is still under a point between two index lines. The prediction in the
%  paragraph above is the useful part of this note: THIS NUMBER IS NOT A
%  CONSTANT, it is a function of how long the index is, and the index only
%  ever grows. Raise it when a build says so and do not go looking for a
%  cleverer fix.
%
%  AND AGAIN AT P17, with one detail worth keeping: 10.8 pt and 4.8 pt on the
%  LAST page of `main-pl.ind`, which is the page where the shrink has to do
%  its work because the material has nowhere else to go. An interior column
%  that will not fit pushes an entry to the next page; the final one cannot,
%  so it must shrink or overflow, and it is reliably the fullest page of the
%  four because \raggedbottom lets every page before it end short. Nine tenths
%  went to two and a half, which is still two and a half points spread over a
%  column of forty entries and invisible between two index lines. The
%  prediction two paragraphs up has now been right three times running; treat
%  the number as a function of the index's length and nothing else.
%  AND AT P18, the fourth raise in four programs -- 10.6 pt in one column of
%  `main-pl.ind`, two and a half points to three and a half.
%
%  AND AT P19 THE ADVICE ABOVE WAS FALSIFIED, AND THEN THE MEASUREMENT THAT
%  FALSIFIED IT WAS FALSIFIED TOO. Both halves are worth keeping, because the
%  second is this repository's own recurring defect and it was committed.
%
%  First: P19's index overflowed at 3.5 pt and the number was raised, and a
%  sweep taken WHILE THE PROGRAM WAS STILL BEING WRITTEN reported that 2 and
%  6 both failed builds that 4.5 cleared. That table was quoted here and in
%  CLAUDE.md as though it described the shipped tree. It did not: it described
%  a tree that no longer exists, which is exactly what this project's own rule
%  says about page counts and the overfull multiset -- RE-MEASURE FROM THE
%  BUILD IN FRONT OF YOU; a pagination measurement does not survive a change
%  to the material being paginated. Re-swept against the finished tree:
%
%      shrink | en | pl | en-a4 | pl-a4
%      -------+----+----+-------+-------
%       3.0   | ok | ok |  ok   |  ok
%       3.5   | ok | ok |  ok   |  ok
%       4.0   | ok | ok |  ok   |  ok
%       4.5   | ok | ok |  ok   |  ok
%       5.0   | ok | ok |  ok   |  ok
%       5.5   | ok | ok |  ok   |  ok
%       6     |  - |  - |  ok   |  26.3 pt
%       7     |  - |  - |  ok   |  26.3 x2
%      10     |  - |  - |   -   |  616.8 + 90.8
%
%  So on THIS machine the constant is not critical anywhere in [3.0, 5.5] and
%  falls off a cliff at 6. Ten points is CATASTROPHIC rather than merely
%  insufficient: more shrink lets TeX believe it can cram another column's
%  worth onto a page, and it then overflows by a whole column.
%
%  Second, and this is why the value here is 5.5 rather than anything in the
%  middle of that range: CI FAILED `en (a4)` AT 4.5 BY 18.29 pt ON SOURCE
%  THIS CONTAINER BUILDS WITH ZERO. The index is where the two installations
%  diverge worst -- CI sets the same entries in three pages where this
%  container needs four, so its columns are fuller and demand more shrink --
%  and a sweep taken on one machine cannot choose a value for the other.
%
%  AND THE RAISE WORKED, PARTLY, WHICH SETTLED THE MECHANISM. At 5.5 CI's box
%  went from 18.29 pt to 9.29 pt -- exactly nine points for one point of extra
%  shrink per entry -- so the shrink DOES reach it and the direction was right.
%  What it also showed is that no single \parskip value can serve both
%  machines: CI wants more than 5.5 and this container's `main-pl-a4` breaks at
%  6, by 26.3 pt. The two disagree and the knob is one-dimensional.
%
%  SO THE REMEDY IS A SECOND SOURCE OF SHRINK, and the point of it is that it
%  does NOT scale with the page's contents. A column holds some forty-five
%  entries, so one more point on each is forty-five points of extra capacity
%  and TeX packs more -- which is exactly why the constant is non-monotonic.
%  \indexspace appears three or four times a page whatever the entries are, so
%  six more points of shrink on each is about twenty points, bounded, and it
%  absorbs a residual without changing how much TeX is willing to cram. That is
%  the difference between giving a page slack and giving it appetite.
%
%  AND AFTER FOUR CI CYCLES THE CONSTANT WAS ABANDONED, WHICH IS THE ACTUAL
%  ANSWER. The residual grew with the index and the index grows with every
%  program: 18.29 pt at P19, 9.29 pt after the raise to 5.5, cleared by the
%  bounded \indexspace shrink, then 33.29 pt the moment P21's entries landed.
%  No value of a shrink can hold a target that moves every time a program is
%  written, and the two machines disagree about where the window is anyway.
%
%  So the index's columns are simply given LESS ROOM than the text block:
%  three lines of headroom, which absorbs about forty points of residual by
%  construction, on any machine. It cannot backfire the way shrink does,
%  because it REDUCES what TeX will pack onto a column rather than increasing
%  it -- and an index column ending three lines short of the body's measure is
%  what every index in print looks like. The \parskip shrink drops back to a
%  point, which is all it was ever for.
%
%  THE GENERALISABLE HALF: when a rigid region keeps needing a few more points
%  and the requirement grows with the content, stop tuning the slack and take
%  the room away instead. A knob that has to be re-tuned per program is not a
%  fix, and this one was re-tuned five times.
%
%  A process note that cost a CI cycle, because it will happen again. The
%  raise to 5.5 was made, and then a BACKGROUND SWEEP SCRIPT still running in
%  the tree restored 4.5 on its way out, so the commit carried the old value
%  and CI reported 18.28874 pt a second time -- to the ten-thousandth of a
%  point. An identical measurement after a change is this repository's own
%  signal that the change did not reach what was measured (see the CI vbox
%  chased into the answers appendix, above). Here it was even simpler than
%  that: the change did not reach the FILE. Re-read the constant out of the
%  file immediately before committing it, not several steps earlier, and do
%  not leave a script that rewrites the tree running behind you.
%
%  THE RULE, and it now has both halves:
%    * Sweep against all four builds and pick a value that clears every one;
%      do not assume the direction, and do not carry a sweep across a change
%      to the material.
%    * The window is narrow and the two machines disagree about where it is,
%      so CI is the second measurement and not a formality. When a value
%      clears here and fails there, move within the locally clean range
%      TOWARDS more shrink -- the complaint is that a column could not be
%      compressed enough -- and stop at the cliff rather than past it.
%  \vfuzz stays rejected: raising it hides real overfull vboxes everywhere
%  else, which is how a gate goes quiet.
%  AND EVERY ONE OF THOSE FIVE CYCLES WAS SPENT ON THE WRONG MECHANISM.
%  P23 read the packages instead of the constant and found it. THE INDEX IS
%  NOT A \twocolumn REGION AT ALL. `imakeidx` is loaded without its
%  `original` option, and in that mode it does not merely add the index to
%  the contents -- it \renewenvironment{theindex} on top of `multicols`
%  (imakeidx.sty, the \ifimki@original branch). So book.cls's twocolumn index
%  never runs here, and neither does any of the machinery the comments above
%  reason about:
%
%    * \raggedbottom sets \@textbottom, which \@makecol reads. multicol
%      installs its own output routine and never calls \@makecol, so the
%      \raggedbottom above has been INERT since the day it was added. Its
%      analogue inside multicols is \raggedcolumns, and that is the switch
%      the last column's balancer actually reads (\ifshr@nking in
%      \balance@columns, multicol.sty).
%    * \vfuzz is inert too, and provably so: multicol sets \vfuzz\z@ itself
%      immediately before the \vbox to that balances the final page. A value
%      set in this environment's body cannot survive that assignment. THAT is
%      why CI came back with 8.28874 pt a second time, to the ten-thousandth
%      of a point, after \vfuzz was added -- which is this file's own signal
%      that a change did not reach what was measured, arriving for the third
%      time in one pass.
%    * \flushcolumns is multicol's default, and it is exactly the rigid
%      setting the comments above diagnose: every column held to \@colroom
%      with nothing to give. The overfull vbox was always on the LAST index
%      page because that is the only page multicol BALANCES rather than
%      splits, and a balanced column under \flushcolumns must come out exact.
%
%  So the constant that was swept five times, the \textheight reduction that
%  replaced it, and the \vfuzz that replaced that were all compensating for a
%  switch that was never thrown. THE GENERALISABLE FINDING, and it is worth
%  more than the fix: A REMEDY THAT IS CORRECT FOR THE ENVIRONMENT YOU THINK
%  YOU ARE IN IS INERT IN THE ONE YOU ARE ACTUALLY IN, AND AN INERT REMEDY
%  LOOKS EXACTLY LIKE ONE THAT DID NOT GO FAR ENOUGH. Every cycle above read
%  the residual as evidence that the number needed raising. Before sweeping a
%  constant a second time, check that the macro you are setting is read by
%  the code that produces the complaint.
%
%  What is left below is the mechanism and two shrinks that cost nothing:
%  \raggedcolumns so a balanced column may end short, \raggedright so index
%  lines do not stretch, and shrink on \parskip and \indexspace so the
%  balancer has somewhere to take a residual from. The \textheight reduction
%  and the \vfuzz are both gone: the first was a compensator tuned against a
%  mechanism that was not running, and the second could not have worked.
\apptocmd{\theindex}{%
  \raggedcolumns\raggedright
  \setlength{\parskip}{0pt plus 0.3pt minus 1pt}%
  % book.cls sets \indexspace to 10pt plus 5pt minus 3pt. It appears three or
  % four times a page whatever the entries are, so extra shrink here is
  % bounded rather than proportional to the number of entries -- which is
  % what a balancer wants. 9pt and not more: the natural size is 10pt, and a
  % shrink above that lets the glue go negative and closes two entries up.
  \renewcommand\indexspace{\par \vskip 10pt plus 5pt minus 9pt\relax}}{}{%
  \PackageWarning{mfabook}{Could not patch theindex for ragged setting}}
