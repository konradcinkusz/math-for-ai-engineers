\chapter{Notation and Symbols}
\label{app:B}

\noindent
This appendix records the four places where mathematical usage is split and
the book has had to choose, and the one rule that decides how a name is spelt
in each edition. It is deliberately not a table of every symbol: a reader who
has never seen $\sum$ meets it built from nothing in Program~\ref{prog:F04},
and the subscript underneath it in Program~\ref{prog:F02}, so the job a symbol
table would do is done by the programs that introduce the symbols.

\section{The decisions this book has taken}
\label{sec:appB-decisions}

\noindent
Where mathematical usage is split, a book must choose, and the choice is worth
more to a reader than the convention itself. These are the four that bite.

\begin{notationbox}
\textbf{A logarithm here carries its base, and the build enforces it.}
Natural logarithms are $\ln$; base-two logarithms are $\logb{2}$. A bare
$\mfalogplain$ is a build error and the parity lint names the file and the
line before the build gets that far.

There are two kinds of place where the ban is lifted, and both are deliberate.
One is where the ban itself is the subject: this appendix, and
Program~\ref{prog:F03} §2, which has the reader meet the collision before it
is named. The other is \textbf{inside an $O$}, where changing base multiplies by a
constant and a constant is exactly what the notation discards \dash{} so
$O(n \mfalogplain n)$ names one class of growth for every base at once, and
writing a base inside it would suggest a distinction that does not exist.
Program~\ref{prog:P03} has that as a notation box and
Program~\ref{prog:P16} uses it. The count of such places is deliberately not
stated here, because a tally decays and nothing can check it.

The reason is that the two readerships this book serves have been taught
opposite conventions. In Polish textbooks a bare logarithm means base ten. In
machine-learning writing it means base $e$. The same three characters carry
opposite meanings, and they collide hardest in exactly the programs where it
matters most: entropy is quoted in bits and cross-entropy in nats, and those
are two programs apart.

A global convention stated once in an appendix is not a fix for that. Writing
the base costs two characters, and the build refuses a bare logarithm rather
than trusting anybody to remember.
\end{notationbox}

\begin{notationbox}
\textbf{Vectors are columns.} $x \in \R^{n}$ is a column; $x\T$ is a row.
Polish schooling also writes an arrow above the letter; the papers this book is
training you to read do not, so neither does this book.

A vector is set in ordinary italic wherever nothing else in the expression
could be mistaken for one, which is most of the book \dash{}
Programs \ref{prog:F09}, \ref{prog:P04} and \ref{prog:P05} introduce vectors
and set every one of them in italic. It is set \textbf{bold} where a vector
and a matrix share an expression and the shapes are the point, as in
$\vect{y} = W\vect{x}$: that is Program~\ref{prog:P18}'s subject throughout,
and the handful of later places that quote it.

\textbf{Matrix derivatives use numerator layout}, declared in Program~P18 and
never assumed silently. This is not a national split, it is a discipline split,
and it is the origin of a good half of the transpose confusion in accounts of
backpropagation.
\end{notationbox}

\begin{notationbox}
\textbf{Intervals use square brackets:} $\intcc{a}{b}$ is closed,
$\intoo{a}{b}$ is open. Polish schooling writes $\langle a, b\rangle$ for the
closed interval. ISO 80000-2, and every paper you are going to open, do not.
The book follows the papers. The first interval a reader meets is in
Program~F3, and no program stops to explain the choice, so this appendix is
where it is recorded.
\end{notationbox}

\begin{notationbox}
\textbf{Variance is $\Var(X)$ and expectation is $\Ex[X]$.} Polish teaching
materials still write $D^{2}(X)$ for the variance today, alongside $\Var$; this
is current usage and not a historical curiosity, and Program~P24 states the
equivalence where the concept is introduced. $M(X)$ for the expectation is
residual and gets a sentence rather than a box.
\end{notationbox}

\section{The keyboard test}
\label{sec:appB-keyboard}

\noindent
The Polish edition writes \emph{tg} for the tangent, where this English
edition writes \emph{tan} \dash{} and both editions write \code{tanh} for the
hyperbolic tangent rather than the \emph{tgh} Polish mathematical writing
sets. That looks inconsistent. It is the rule working.

Both spellings are set here as literal text rather than through the notation
macros, and they have to be: a macro renders in the edition you are holding,
so writing this paragraph with $\tg$ would print the same word in both columns
and describe a divergence the page does not show.

\begin{note}
\textbf{If you will type the token into a computer, both editions use the
spelling you will type. If you will only ever read or write it, the Polish
edition uses the Polish form.}

Nobody types \emph{tg} into a program, so the Polish edition sets \emph{tg},
\emph{ctg} and \emph{arc tg}, as Polish mathematics does \dash{} through
$\tg$, $\ctg$ and $\arctg$, which set the English forms here and the Polish
forms there. But \code{tanh} is
\code{torch.tanh} \dash{} it is an activation function before it is a
function of a real variable, and a Polish reader who learns \emph{tgh} will not
find it in any library. Polish mathematical writing does set \emph{tgh}, and no
program stops to say so, which makes this appendix the record.
\end{note}
